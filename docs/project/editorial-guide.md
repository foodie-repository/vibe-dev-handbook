# 편집 가이드

## 문체

- 존댓말을 사용합니다.
- 먼저 결론을 말하고 이유와 예외를 설명합니다.
- “쉽습니다”, “그냥”, “알아서”, “완벽하게” 같은 과장 표현을 피합니다.
- 한 문단은 하나의 핵심 주장에 집중합니다.
- 영문 용어는 첫 등장에 한국어 뜻과 함께 표기합니다.

## 설명의 네 층

1. **한 문장 정의**: 기억할 최소 문장
2. **구조**: 무엇과 연결되는지
3. **실제 신호**: 화면, 로그, 파일, 명령에서 어떻게 나타나는지
4. **판단법**: 언제 선택하고 무엇으로 확인하는지

## 비유 규칙

좋은 비유는 새로운 개념의 관계를 보여줍니다. 예를 들어 API를 식당 주문 창구에 비유할 수 있습니다. 그러나 API는 사람처럼 애매한 말을 알아서 해석하지 않고, 정해진 형식과 권한을 요구합니다. 반드시 이런 한계를 덧붙입니다.

## 코드 사용

코드가 목적이 아니라 증거일 때만 사용합니다.

- 명령어는 결과와 위험을 함께 설명합니다.
- 긴 구현 코드는 피하고 입력·출력과 경계를 보여주는 최소 예시를 사용합니다.
- 독자가 복사 실행할 수 있는 예시는 운영 데이터와 비밀정보를 요구하지 않아야 합니다.

## 제목 계층

Starlight가 frontmatter의 `title`을 페이지 최상위 제목(H1)으로 출력합니다. 공개 본문에는 H1을 다시 쓰지 않고 `##` 수준부터 시작합니다. 코드 블록 안의 `#` 주석은 본문 제목으로 보지 않습니다.

## 교차 연결

같은 개념을 여러 장에서 다시 정의하지 않습니다. 용어집이나 중심 장으로 연결하고, 현재 장에서는 해당 맥락에서 달라지는 점만 설명합니다.

## 콘텐츠 상태

`seed`, `draft`, `review`, `ready`의 의미와 승격 증거는 `docs/project/content-lifecycle.md`를 따릅니다. 원고 분량이나 자동 검사 통과만으로 상태를 올리지 않습니다.
