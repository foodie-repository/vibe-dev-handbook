# 정보 구조 설계

## 기본 원칙

이 가이드는 도구별 설명이 아니라 독자의 **의사결정 능력**이 자라는 순서로 구성합니다.

1. 소프트웨어를 시스템으로 보는 법
2. 로컬 환경과 실행 단위 이해
3. 브라우저에서 데이터 저장소까지의 흐름
4. 요구사항을 설계와 검증으로 변환
5. 변경을 안전하게 관리하고 배포·운영
6. 그 전체 과정을 AI 에이전트와 수행

최신 유행 개념은 11부에 둡니다. 컨텍스트나 하네스는 기본 개발 구조를 대체하는 별도 마법이 아니라, 에이전트가 그 구조 안에서 안정적으로 일하도록 만드는 운영 계층이기 때문입니다.

## 세 가지 학습 경로

- **빠른 지도**: 2시간 안에 전체 지형과 핵심 용어 파악
- **Build Track**: 소규모 모임 일정·참가 신청 웹앱을 기본 사례로 요구사항부터 배포까지 따라가고, 데이터 분석의 판단 차이는 주가 데이터 분석 대시보드로 비교하기
- **Deep Track**: 각 영역의 설계 선택과 실패 모드까지 학습

공개 경로의 구체적인 문서 목록과 읽는 순서는 `src/content/docs/start-here/learning-paths.md`를 단일 진실 공급원으로 사용합니다. 홈과 내부 프로젝트 문서는 경로를 다시 정의하지 않고 이 문서를 참조합니다.

사례는 모든 장에 같은 분량으로 반복하지 않습니다. 일반 개발 개념은 웹앱을 기본으로 설명하고 데이터 원천·품질·재현성·해석 책임이 결론을 바꾸는 지점에만 주식 분석 사례를 함께 사용하며, 12부에서는 두 사례를 각각 독립 캡스톤으로 제공합니다. 상세 적용 규칙은 `docs/superpowers/specs/2026-08-07-dual-case-study-system-design.md`를 따릅니다.

## 두 가지 이용 방식

이 핸드북은 처음부터 끝까지 따라가는 학습 경로와, 현재 문제에 필요한 내용만 찾는 참조 경로를 함께 지원합니다.

- **순차 학습**: 시작하기, 핵심 개념, Build Track, 캡스톤의 선후 관계를 따라 전체 개발 흐름과 사고법을 쌓습니다.
- **검색·참조**: 사이트 검색, 용어집과 장 사이의 교차 링크를 이용해 `fallback`, `인증과 인가`, `배포와 릴리스의 차이`처럼 지금 필요한 질문에서 진입합니다.

검색으로 바로 들어온 문서도 앞 장 전체를 읽었다고 가정하지 않습니다. 제목과 설명은 질문과 답의 범위를 분명히 하고, 한 문장 정의·시스템 위치·판단 규칙·관련 용어 링크를 제공하며, 필수 선행 개념이 있으면 그 이유와 함께 연결합니다. 한국어 표현, 널리 쓰이는 영문 용어와 약어는 첫 등장과 용어집에서 짝지어 검색할 수 있게 합니다.

## 지식과 도구의 계층

핵심 설명은 `영속 개념 → 사례 적용 → 현재 도구 매핑 → 교체 가능한 실습·부록`의 네 층으로 구성합니다. 아키텍처, 프레임워크의 역할과 선택 기준, 개발 절차, 방법론, 용어와 판단 질문은 제품 이름 없이 이해할 수 있어야 합니다. Supabase·Vercel·Codex Sites·Claude Code·Codex 같은 제품은 공식 자료를 확인한 시점의 적용 예로만 사용하고, 버튼 위치·요금·명령처럼 빨리 바뀌는 내용은 날짜와 범위를 표시해 핵심 본문과 분리합니다.

## 장의 정보 계층

각 장은 가능한 한 다음 질문 순서로 답합니다.

- 이것은 무엇이며 왜 필요한가?
- 전체 시스템의 어디에 있는가?
- 앞뒤 구성요소와 어떤 약속으로 연결되는가?
- 무엇이 잘못될 수 있는가?
- 개발자는 어떤 증거로 판단하는가?
- AI에게 어떤 범위와 검증 기준을 줘야 하는가?

## 깊이 관리

모든 용어를 동일한 깊이로 설명하지 않습니다.

- 반드시 판단해야 하는 개념: 독립 장
- 작업 로그에서 자주 만나는 개념: 용어집 + 관련 장 연결
- 특정 기술에 종속된 개념: 사례 또는 외부 공식 문서로 연결
- 컴퓨터과학 이론: 결정을 이해하는 데 필요한 수준으로 제한
