# 데이터 분석가의 대시보드 사례 검토 준비 기록

## 목적과 현재 상태

이 문서는 공식 Build Track 열두 번째 장인 `src/content/docs/12-case-studies/analytics-dashboard-case-study.md`의 자체 품질 점검과 독립 검토 요청 범위를 기록합니다. 원고는 교육용 가상 반도체 대시보드의 한 사용자 작업을 문제·요구사항·데이터 계약·품질 게이트·전달·화면·테스트·Git·배포·운영·AI 작업 인수까지 연결하고 Opus 독립 검토 요청과 지적 반영을 마친 `review` 상태이지만, 사람 기술·데이터·편집 검토와 비개발자 독자 테스트를 아직 통과하지 않았습니다.

실제 반도체 원천과 수치를 사용하지 않으며 기업 A·B와 한 분기 지표는 교육용 가상 시나리오입니다. 기존에 확인한 소프트웨어 생명주기·웹 UI·접근성·Git·정적 배포 출처만 적용했고, data contract·canonical schema·data lineage·freshness의 직접 공식 출처, 방문자 측정의 관할별 개인정보 기준과 실제 원천의 지표 정의·이용 조건·재배포 허용 범위는 네트워크 조사 승인 후 확인할 대기로 남겼습니다.

2026-08-05 오전 7시 KST 한도 초기화 이후 호스트 Claude Code의 `claude-opus-5`, 추론 강도 `max`, `Read` 전용 권한으로 아래 계약을 실행해 정상 결과를 받았습니다. P0는 없고 P1 9건·P2 18건·독립 루브릭 16/18이었으며, Codex 재판정과 반영 내용은 `docs/project/reviews/2026-08-05-analytics-dashboard-case-study-opus5-review.md`에 기록했습니다. 이 준비 문서 자체는 독립 검토 완료나 사람 검토를 증명하는 `reviewEvidence`가 아닙니다.

## Build Track 연결 감사

ROADMAP의 “사례 하나를 따라 요구사항에서 배포 검증까지 연결” 조건을 기준으로, 최종 사례가 앞선 Build Track 11개 장을 이름만 나열하지 않고 실제 판단과 증거 절에서 사용하는지 점검했습니다.

| 앞선 Build Track 장 | 사례 안의 직접 연결 |
|---|---|
| 소프트웨어는 시스템입니다 | 공개 원천부터 사용자·운영 증거까지 일곱 책임과 실패 역추적 |
| 클라이언트·서버·풀스택 | 정적 전달과 API 선택, 사용자 행동에서 전달 데이터와 화면까지의 책임 |
| HTTP 요청과 응답 | API 전환 시 추가되는 요청·응답·오류 계약과 Network 증거의 한계 |
| API·데이터베이스·인증 | 데이터 크기·비밀·사용자별 권한·쓰기 상태에 따른 서버와 영속 저장 도입 조건 |
| 브라우저·DOM·렌더링 | 초기·로딩·정상·결측·경고·차단·실패 상태와 접근 가능한 표현 |
| PRD·두 종류의 SDD·TDD | 사용자 문제, R-01~R-05 요구, C-01~C-04 제약과 추적성 |
| 테스트 전략 | 요구별 fixture·계약·브라우저·재현·복원 증거와 보장하지 않는 범위 |
| Git과 GitHub는 다릅니다 | 코드·계약·합성 fixture·데이터 권리·비밀·버전 매니페스트 경계 |
| 빌드·배포·도메인·DNS | 아티팩트 구성과 로컬 빌드·원격 CI·공개 URL 성공의 구분 |
| 로그·모니터링·백업 | freshness·알림·중지·격리 복원·smoke test와 운영 학습 순환 |
| AI 코딩 에이전트와 일하는 법 | 계약부터 인수 증거까지 다섯 수직 조각과 권한·완료 보고 계약 |

본문의 관련 장 절에는 11개 문서 링크가 모두 있고 참조 검증을 통과했습니다. 이 감사는 연결의 존재와 범위만 증명하며, 각 설명의 기술 정확성·교육 효과·실제 원천 권리 또는 공개 배포 성공을 증명하지 않습니다.

## 자체 점검에서 보완한 범위

1. 가상 기업 A·B의 한 분기 지표 비교를 교육용 시나리오로 고정하고 실제 수치·원천·투자 판단을 대신하지 않는 경계를 명시했습니다.
2. 분석 노트북과 운영 제품의 차이를 개인 실험 노트와 측정 장비 비유로 설명하고 변하는 소프트웨어 환경의 한계를 추가했습니다.
3. R-01 비교·R-02 설명 가능성·R-03 불확실성·R-04 재현성·R-05 운영 인수와 C-01~C-04 제약을 추적 가능한 요구로 작성했습니다.
4. 가로형 다이어그램을 모바일에서도 읽을 수 있는 세로형 공개 원천·수집·품질·저장·전달·UI·사용자·운영 증거 순환으로 개선했습니다.
5. 데이터 계약에 식별자·지표 정의 버전·기간·값·값 상태와 결측 사유·단위·통화·원천 버전과 체크섬·시간·변환·데이터셋 버전·품질 상태를 포함하고 canonical schema와 data lineage의 범위·한계를 설명했습니다.
6. 후보 값의 최종 게시 판정인 통과·경고·차단과 임시 사람 확인 대기를 구분하고, 차단·검토 대기 값을 공개하지 않은 채 마지막 정상 버전과 갱신 상태 메타데이터를 유지하도록 연결했습니다.
7. 정적 전달과 API를 데이터 크기·갱신·비밀·사용자 상태·쿼리·운영 책임으로 선택하고 첫 수직 조각은 정적 전달로 결정했습니다.
8. 사용자 선택에서 정적 데이터·표·차트·출처·품질 상태까지의 흐름과 API 전환 시 추가되는 책임을 구분했습니다.
9. 초기·로딩·정상·0·결측·오래됨·경고·차단·실패 상태와 표·키보드·색상 외 표현·보조 기술 확인을 추가했습니다.
10. R-01~R-05마다 데이터·계약·브라우저·재현·복원 증거를 연결하고 자동 테스트가 데이터 권리·사용자 이해·공개 운영을 보장하지 않는다고 밝혔습니다.
11. 코드·계약·합성 fixture·원천 기록·버전·체크섬·매니페스트의 Git 경계와 로컬 commit·원격 push·배포의 차이를 추가했습니다.
12. 빌드 아티팩트의 데이터·변환·사이트 버전, 원격·공개 미검증 경계, 관측 신호·알림·격리 복원·smoke test·학습 순환을 추가했습니다.
13. AI 작업을 계약·변환·전달·사용자 흐름·인수 증거의 다섯 수직 조각으로 나누고 읽기 전용·구현 요청 예시를 추가했습니다.
14. 작업 전 12개·공개 전 14개 체크 항목과 한 지표의 추적성 지도 연습을 추가했습니다.
15. 개발 용어집에 data contract·canonical schema·data lineage·data freshness·checksum을 추가하고 기존 공식 출처 적용과 직접 출처 대기 범위를 출처 지도에 기록했습니다.
16. 성공 후보 지표가 방문자 추적을 자동 허가하지 않도록 최소 수집·목적·보존·접근·고지·동의·삭제와 개인정보 없는 집계·동의한 사용성 관찰의 경계를 추가했습니다.

15. 적용한 기존 공식 출처가 주장 범위를 직접 뒷받침하는지, 추가로 확인할 데이터·원천·권리 1차 자료를 구분하고 품질 루브릭 9개 항목을 0~2점으로 재평가해 주세요.

결과는 `P0 치명 오류`, `P1 review 전 필수`, `P2 개선 권장`, `잘된 점`, `루브릭 점수`, `추가 출처 확인 목록` 순으로 작성하고 각 지적에 대상 제목이나 짧은 대상 문구와 근거를 포함해야 합니다. 웹 검색, 파일 수정, Bash, 외부 플러그인과 하위 에이전트는 사용하지 않습니다.

## 독립 검토 결과

- 실제 모델·강도: `claude-opus-5`, `max`
- 종료 상태: 종료 코드 0, 정상 결과 본문 생성
- 결과: P0 0건, P1 9건, P2 18건, 루브릭 16/18
- 입력 무변경: 검토 전후 29개 파일의 결합 SHA-256 일치
- Codex 판정: P1 8건 수용·1건 부분 수용, P2 16건 수용·2건 부분 수용 또는 추가 근거 필요
- 상태: 독립 검토 요청과 지적 반영을 마쳐 `review`, 직접 출처와 사람 검토가 남아 `ready` 금지

전체 실행 사실·지적·재판정·남은 출처 목록은 [Opus 5 교차검증 기록](2026-08-05-analytics-dashboard-case-study-opus5-review.md)에 있습니다.

## 승격 경계

Opus 검토 결과의 각 지적은 Codex가 실제 원고와 프로젝트 규칙에 대조해 수용·부분 수용·기각으로 재판정했습니다. 이 요청 증거는 `review`의 시작을 표시할 수 있지만, 데이터 전문가의 기술 검토, 편집 검토와 비개발자 독자 테스트, 직접 출처 확인을 완료하기 전에는 `ready`로 승격하지 않습니다.
