# 로그·모니터링·백업 검토 준비 기록

## 목적과 현재 상태

이 문서는 공식 Build Track 열 번째 장인 `src/content/docs/10-deployment-operations/logs-monitoring-backup.md`의 자체 품질 점검과 독립 검토 요청 범위를 기록합니다. 원고는 배포 뒤 사용자 영향 신호, 감지·안정화·복구·검증·학습 순환과 백업·복원 증거를 연결하는 `draft`이지만 작성 맥락을 공유하지 않은 독립 기술·편집 검토와 비개발자 독자 테스트를 아직 통과하지 않았습니다.

2026-08-05 현재 호스트 Claude Code 로그인과 Pro 구독은 확인됐지만 `claude-opus-5`, 추론 강도 `max` 요청은 원고 읽기 전에 오전 7시 KST 재설정 세션 한도로 종료됩니다. 한도 초기화 이후 아래 계약으로 이 장을 읽기 전용 독립 검토 대기열에 추가합니다. 계정 식별 정보는 기록하지 않으며, 이 준비 문서는 독립 검토 요청이나 완료를 증명하는 `reviewEvidence`가 아닙니다.

## 자체 점검에서 보완한 범위

1. 로그·지표·트레이스·모니터링·관측 가능성·대시보드·알림을 서로 다른 신호·능력·행동 경계로 정의했습니다.
2. 식당 운영 기록 비유에 분산 경로·샘플링·계측 누락·복제·암호화와 스키마 호환성의 한계를 추가했습니다.
3. 사용자·시스템 신호에서 감지·범위 확인·안정화·복구·검증·학습으로 이어지는 세로형 운영 순환 SVG와 Mermaid 원본을 추가했습니다.
4. 구조화 로그 문맥과 비밀·개인정보 최소화, 사용자 결과와 시스템 원인 지표, 트레이스 샘플링·누락 한계를 구분했습니다.
5. 내부 건강·smoke test·외부 합성 확인·실제 사용자 신호의 증거 범위를 분리했습니다.
6. SLI·SLO·SLA를 측정·내부 목표·외부 계약으로 구분하고 성공 정의·기간·분자·분모의 필요성을 명시했습니다.
7. 행동 가능한 알림에 사용자 영향·긴급성·담당자·첫 확인 위치·안전한 자동 조치와 거짓 양성·음성 조정을 연결했습니다.
8. 이 저장소의 정적 사이트 구조에서 실제로 필요한 로컬 빌드·원격 CI·공개 URL·도메인 신호와 재현 가능한 `dist/`·원본 자산의 복구 우선순위를 구분했습니다.
9. 동기화·복제·스냅샷·버전 관리·내보내기와 백업을 구분하고 RPO·RTO를 목표로 정의해 격리된 복원 시험의 직접 증거와 연결했습니다.
10. 인시던트 대응·런북·사후 검토, 읽기 전용 AI 지시와 운영 신호·백업 복구·인수인계 체크리스트를 추가했습니다.

1. 로그·지표·트레이스·모니터링·관측 가능성·대시보드·알림의 정의와 관계가 정확하고 도구·조직별 용어 차이를 충분히 표시하나요?
2. 구조화 로그의 문맥과 비밀·개인정보 최소화·접근·보존 경계가 비개발자에게 안전하게 설명됐나요?
3. 수요·결과·시간·여유와 데이터 최신성·정확성을 연결한 지표 설명이 사용자 영향과 시스템 원인을 과장 없이 구분하나요?
4. 트레이스의 분산 경로·샘플링·계측 누락과 지표·로그의 상호 보완 설명이 정확한가요?
5. 내부 건강 확인·smoke test·외부 합성 확인·실제 사용자 신호의 역할과 자동 조치 위험이 정확한가요?
6. SLI·SLO·SLA의 측정·목표·계약 구분과 성공 정의·기간·제외 조건 설명에 중요한 누락이 있나요?
7. 대시보드와 행동 가능한 알림의 영향·긴급성·담당자·거짓 양성·음성·자동 완화 경계가 실제 운영 판단에 도움이 되나요?
8. 감지·범위 확인·안정화·복구·검증·학습 순환이 원인 규명과 사용자 피해 완화의 우선순위를 안전하게 설명하나요?
9. 인시던트 역할·사실과 가설·작은 변경·런북·사후 검토가 비개발자에게 과하거나 중요한 책임을 누락하지 않았나요?
10. 백업·동기화·복제·스냅샷·버전 관리·내보내기의 구분과 원본 실패에서의 격리 설명이 정확한가요?
11. RPO·RTO의 정의·예시·자산별 차이와 실제 백업 간격·복원 시험의 관계가 정확한가요?
12. 복원 시험 단계가 무결성·스키마·애플리케이션·권한·외부 상태·사용자 흐름과 실제 소요 시간을 충분히 검증하나요?
13. 정적 사이트와 데이터 서비스, 현재 저장소의 관측·백업 사례가 실제 구조와 미검증 원격 경계를 정직하게 표시하나요?
14. AI 읽기 전용 지시, 세 체크리스트와 연습이 비개발자의 운영 완료 판정 능력을 관찰 가능하게 검증하나요?
15. 현재 출처가 직접 뒷받침하지 못하거나 추가 표준·공식 1차 자료 확인이 필요한 주장과 품질 루브릭 9개 항목의 0~2점·치명 항목 여부를 판정해 주세요.

결과는 `P0 치명 오류`, `P1 review 전 필수`, `P2 개선 권장`, `잘된 점`, `루브릭 점수`, `추가 출처 확인 목록` 순으로 작성하고 각 지적에 대상 제목이나 짧은 대상 문구와 근거를 포함해야 합니다. 웹 검색, 파일 수정, Bash, 외부 플러그인과 하위 에이전트는 사용하지 않습니다.

## 승격 경계

Opus 검토 결과가 생성되면 Codex가 각 지적을 실제 원고와 프로젝트 규칙에 대조해 수용·부분 수용·기각으로 재판정합니다. AI 검토만으로 상태를 올리지 않으며, 사람 기술·편집 검토와 비개발자 독자 테스트를 완료하기 전에는 `draft`를 유지합니다.
