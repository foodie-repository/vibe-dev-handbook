# 소프트웨어는 시스템입니다 검토 준비 기록

## 목적과 현재 상태

이 문서는 공식 Build Track 첫 장인 `src/content/docs/01-mental-models/software-is-a-system.md`의 자체 품질 점검, 독립 검토 요청과 지적 반영 범위를 기록합니다. 원고는 여섯 시스템 렌즈와 대시보드 사례를 처음부터 끝까지 읽을 수 있고 Opus 5 Max 독립 검토, Codex 재판정, 필요한 최소 보완과 자동 검증을 갖춰 `review`로 표시합니다.

2026-08-05에 호스트 Claude Code 2.1.221의 `claude-opus-5`, 추론 강도 `max`, 계획 모드와 `Read` 전용 계약으로 검토를 실행해 정상 결과를 받았습니다. 손실 없이 보존한 정본은 P0 0건·P1 12건·P2 12건·16/18·치명 항목 없음이며, 11개 입력 파일과 대상 원고의 검토 전후 SHA-256이 일치했습니다. 전체 실행 메타데이터와 결과는 `docs/project/reviews/2026-08-05-software-is-a-system-opus5-review.md`에 있습니다. 이 준비 문서 자체는 독립 검토 요청이나 완료를 증명하는 `reviewEvidence`가 아닙니다.

## 자체 점검에서 보완한 범위

1. 먼저 결론과 왜 필요한가를 추가해 화면 중심 완료 판단의 비용을 구체화했습니다.
2. 프로그램 코드와 실제 소프트웨어 시스템의 실행·데이터·설정·운영 범위를 구분했습니다.
3. 구성요소, 책임, 경계와 인터페이스, 상태, 흐름, 제약과 품질 속성의 질문과 증거를 표로 연결했습니다.
4. 공개 데이터 대시보드를 같은 여섯 렌즈로 분석하고 화면 동작과 시스템 완성도의 증명 범위를 구분했습니다.
5. 저장소·실행 환경에서 보이는 시스템 증거, 판단 규칙, 실패·복구, AI 지시, 체크리스트와 적용 연습을 추가했습니다.
6. component, responsibility, boundary, interface, quality attribute와 constraint를 개발 용어집에 연결하고 장별 출처 적용 범위를 기록했습니다.

## Codex 재판정

Codex는 `docs/project/reviews/2026-08-05-software-is-a-system-opus5-adjudication.md`에서 Opus의 P1 12건과 P2 12건을 실제 원고·프로젝트 규칙·용어집·관련 장·출처 범위에 대조했습니다. P1은 수용 8건·부분 수용 4건, P2는 수용 9건·중복 통합 1건·부분 수용 1건·기각 1건이며, 실제 수정 범위는 렌즈와 시스템 경계, 제약과 품질 우선순위, 상태·흐름·증거 범위, 제품 명칭·용어·출처 경계, AI 작업 계약과 연습, 비유와 그림 한계, 메타데이터와 실패 표현의 7개 묶음으로 정리했습니다.

## 지적 반영 결과

1. 구성요소를 존재·실행되는 부분으로, 책임을 보장할 일과 실패 처리로 구분하고 소유권·사람 승인·아키텍처 결정의 경계를 보완했습니다.
2. 협상할 수 없는 제약을 먼저 고정한 뒤 품질 속성의 우선순위를 정하도록 판단 규칙과 체크리스트를 나눴습니다.
3. 정적 사본의 수명, 사용자 조회·정기 갱신·실패 복구의 서로 다른 시작 조건, 로컬 빌드와 공개 URL 증거를 구분했습니다.
4. 브라우저별 개발자 도구 명칭 한계, `flow` 용어집 표제어, 관련 용어와 출처가 직접 증명하지 못하는 범위를 동기화했습니다.
5. AI 작업 지시에 네트워크·설치·파일 수정·Git·배포·비밀정보의 금지 범위를 추가하고 독자가 같은 계약을 직접 작성하는 연습을 넣었습니다.
6. 집 비유의 일곱 번째 렌즈 오해와 완공 프레임, 재사용한 대시보드 그림의 역할·되먹임 단순화를 설명했습니다.
7. 검색 설명과 백엔드 책임·상태 사본의 실패 표현을 바로잡고, 기각한 P2-12의 불필요한 표 작성 요구는 반영하지 않았습니다.

반영 전 대상 SHA-256은 `80b15ad9ed7247045bba265579f4bcc61896c1ee73c54a6bdbcced0d31b37b28`, 반영 후 대상 SHA-256은 `29d9985d86b7e4923c8861bc443364130249fcd766cfbb53559ff5ca471bcaa2`입니다. frontmatter의 `request:`는 실제 Opus 검토 결과 기록을 가리키고 `automated:`는 2026-08-05의 `npm run check`를 가리킵니다.

1440×1000과 390×844 렌더링에서 H1 1개, `검토 중` 배지, H2·H3 23개, 표 4개, 체크 항목 14개, 코드 블록과 SVG 대체 텍스트를 확인했습니다. 두 폭 모두 페이지·표·코드 블록의 가로 넘침과 콘솔 오류·경고는 0건입니다.

## 승격 경계

원고는 자체 루브릭 17/18·치명 항목 없음, 독립 검토 요청과 정상 결과, Codex 재판정과 지적 반영, `request:`·`automated:` 증거와 `npm run check` 성공을 갖춰 `review`로 표시합니다. 이 상태는 검토가 시작됐다는 뜻이지 출판 준비가 끝났다는 뜻이 아닙니다. 사람 기술·편집 검토, 실제 비개발자 독자 테스트와 직접 출처 확인 없이는 `ready`로 올리지 않습니다.
