## 루브릭 재판정

독립 검토의 현재 15/18을 수용합니다. 자체 18/18은 작성자가 장 전체의 구조와 안전 경계를 넓게 평가한 결과지만, 품질 루브릭의 문언대로 보면 다음 세 항목은 아직 1점이 더 타당합니다.

- 정확성 1점: JWT·MAC과 호환성·인증 실패 일반화의 정의·예외가 완결되지 않았습니다.
- 쉬운 설명 1점: MAC·`expectedVersion`·prepared statement 같은 용어와 입력이 첫 등장에 충분히 풀리지 않았습니다.
- 실전 연결 1점: 복사 가능한 AI 계약과 권한 부정 테스트에 가짜 데이터·허가 환경·운영 변경 금지 경계가 없습니다.

나머지 여섯 항목은 독립 검토의 2점 판정과 일치합니다. 15/18은 점수 문턱만 충족했을 뿐 P1과 출처 동기화가 남아 있으므로 `review` 승격 근거가 아닙니다.

## 후속 반영 묶음

다음 구현 단위에서는 지적을 줄 순서가 아니라 같은 원인의 최소 변경으로 묶습니다.

1. **안전한 실행 경계**: P1-1·P1-2·P1-4를 묶어 테스트 권한·가짜 데이터·비밀·운영 변경·일반화된 외부 인증 실패 응답을 본문·AI 계약·체크리스트에 연결합니다.
2. **정의와 계약 판단**: P1-3·P1-5, P2-1·P2-2·P2-3·P2-9·P2-12·P2-13을 묶어 용어 첫 등장, API 호환성, 내부 스키마와 외부 계약, 자격 전달 경로와 장의 비목표를 정리합니다. JWT를 유지한다면 RFC 7519 직접 확인을 먼저 기록합니다.
3. **관찰 증거와 시각 흐름**: P2-4·P2-5·P2-6·P2-10·P2-11을 묶어 응답 유실 분기, 관찰 주체, 쿼리 값 전달 증거, 비유 소제목과 개발자 도구 링크를 동기화합니다.
4. **출처 일치**: P2-7에 따라 PostgreSQL 고정 버전 URL과 MDN의 설명용 범위를 공개 원고·브리프·출처 지도에서 일치시킵니다.
