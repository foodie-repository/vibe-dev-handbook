## 자체 점검에서 보완한 범위

1. 테스트를 “주어진 조건에서 실제 결과와 기대 결과를 비교하는 실행 활동”, 테스트 전략을 “중요한 위험마다 테스트 수준·데이터·환경·시점·판정 기준과 보완 증거를 선택하는 계획”으로 구분했습니다.
2. verification과 validation의 흔한 경계를 설명하되 조직·표준에 따라 번역과 세부 범위가 달라질 수 있음을 표시했습니다.
3. 단위·통합·계약·종단 간·smoke test를 파일명이나 고정 계층이 아니라 실제 실행 경계와 증명하지 못하는 범위로 설명했습니다.
4. 리뷰·정적 검사·빌드·브라우저·접근성·배포·운영 확인이 테스트 코드와 다르지만 필요한 보완 증거임을 구분했습니다.
5. 영향·가능성·발견 가능성·되돌리기 비용과 가장 작은 관찰 지점으로 위험에서 증거를 선택하는 절차를 추가했습니다.
6. 테스트 오라클, 대역, fixture와 실제 경계의 빈틈을 설명하고 운영 비밀·개인정보를 테스트 데이터에 복사하지 않는 경계를 명시했습니다.
7. flaky test, skipped·expected failure·미실행과 재시도로 숨긴 실패를 성공과 분리했습니다.
8. 공개 데이터 대시보드의 원천·단위·갱신 상태 요구를 변환, 데이터·API, 화면, 사용자 여정과 운영 증거에 연결했습니다.
9. AI의 검증 보고를 명령·위치·환경·범위·종료 코드·수량·수정 전 실패·보완 증거로 재검증하는 읽기 전용 계약을 추가했습니다.
10. 낮음·중간·높은 위험 변경에 필요한 최소 증거와 사람 승인·중지·복구 조건을 구분했습니다.

## 입력 지문과 승격 경계
