## 반영 작업의 수용 기준

- 독자가 클라이언트·서버 역할 축과 프런트엔드·백엔드 책임 축을 등식 없이 설명할 수 있습니다.
- 동적 API와 정적 전달의 대응 단계·책임·증거가 같은 표에서 혼동되지 않습니다.
- 브라우저로 전달되는 값, 공개 환경 HTTPS, 응답 단절 뒤 쓰기 재시도와 외부 입력의 신뢰 경계가 명시됩니다.
- 로컬 서버, 초기 로드와 이후 상호작용, 지속 연결, 동시 요청·늦은 응답과 충돌의 최소 예외가 기본 흐름을 흐리지 않는 범위에서 설명됩니다.
- 정적 전달에도 호스팅·캐시·갱신 시차가 남고 최신성 요구가 동적 전환 신호임을 설명합니다.
- `trust boundary`, `source of truth`, client, server가 원고와 용어집에서 일치하고 인접 장 링크가 유효합니다.
- 직접 확인하지 않은 출처 범위는 `research/source-map.md`의 후속 조사 대기로 남고, 확인된 사실처럼 표현하지 않습니다.
- P1 8건과 P2 13건 각각의 반영 위치 또는 부분 수용 이유를 이 문서에서 역추적할 수 있습니다.
- 공개 원고의 `contentStatus`는 반영·검증·증거 기록이 끝나기 전까지 `draft`를 유지합니다.
