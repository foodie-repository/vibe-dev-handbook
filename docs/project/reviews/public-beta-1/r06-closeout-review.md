- **최소 수정:** 해당 문장의 `R22`만 `R13`으로 바로잡습니다. 최초 reviewer 결과나 원고 본문은 수정할 필요가 없습니다.

그 밖의 주요 점검에서는 다음을 확인했습니다.

**Metadata-only 전이와 증거 연결**

현재 대상 파일을 읽고 제공 전이 문자열을 대조한 결과, Fix1에서 검토한 본문·표·프롬프트·alt·출처 설명은 유지됩니다. frontmatter에 `review`와 요청·재검토·controller 재판정 경로를 추가한 변경입니다. `reviewed_target_sha256`는 Fix1 본문을 검토한 파일을, `current_target_sha256`는 metadata 전이 후 파일을 가리켜 역할이 분명합니다.

`reviewEvidence`의 adjudication 연결은 controller closeout 문서를 가리키며, 그 문서가 실제 finding 재판정과 최초·후속 결과를 다시 연결합니다. 최초 BLOCKED 결과를 현재 PASS 결과처럼 직접 사용하지 않습니다.

**현재 상태와 역사 기록**

최신 프로젝트 요약·행렬·콘텐츠 지도·현재 인벤토리의 수치는 일치합니다. 과거 날짜의 `draft59`, R01만 완료, R06 pending 등의 서술은 역사 기록으로 보존되어 있습니다. 현재 판정은 최신 요약과 행별 표·JSON에 따른다는 구분이 있으므로, 과거 수치 자체를 이번 상태 불일치로 재지적하지 않았습니다.

재판정 문서의 “상태 전이와 closeout은 별도 미완료 단계”라는 문구도 Fix1 후속 확정 시점의 기록입니다. 현재 controller 문서는 이번 전이를 후보로 설명하고 별도 완료 검토·커밋이 필요함을 밝히므로, 이번 응답이나 사후 감사를 이미 통과했다고 주장하지 않습니다.

**코드의 현재 검사와 역사 정규화 — C0/I0/M0**

- `r06PreCloseoutBytes`는 **정확한 경로와 closeout 후 SHA가 일치할 때만** 정해진 치환을 되돌립니다. 치환 대상이 한 번만 존재하는지 검사하고, 결과가 정확한 이전 SHA인지 확인합니다.
- `r06PreFixBytes`는 closeout 전이를 먼저 되돌린 뒤 Fix1 전이를 되돌립니다. 따라서 현재 `review` 파일, Fix1의 `draft` 파일, 최초 BLOCKED 입력을 서로 다른 단계로 취급합니다.
- 허용되지 않은 drift는 정규화되지 않고 원래 바이트로 남습니다. 이후 현재 pin 또는 역사 해시 검사에서 거절됩니다.
- `validateR06Current`만으로는 closeout 이전의 정확한 Fix1 상태를 구별하지 못할 수 있지만, **`validateR06Inputs`가 `validateR06Closeout`도 함께 호출**합니다. 후자가 현재 closeout 후 바이트를 요구하므로 metadata rollback을 역사 정규화 성공으로 통과시키지 않습니다.
- 행렬 검증은 R06의 상태를 `r06Closeout.state`와 대조하며, 현재 대상 해시·최초 BLOCKED·release false·후속 해소 상태의 변조를 거절합니다. R07 이후에 임의의 `review_state`를 넣는 것도 허용하지 않습니다.
- 새 테스트는 현재 pin의 누락·drift·rollback과 정본 증거 변조를 직접 입력 검사까지 연결합니다. 다른 행의 기존 열린 finding을 0으로 만들거나 이관 기록을 지우는 변조 테스트도 유지됩니다.
- R06 이전 단계의 정규화가 호출되더라도 현재 closeout pin 검사가 별도로 남으므로, 이전 증거를 검사할 수 있다는 사실과 현재 상태가 올바르다는 사실을 혼동하지 않습니다.

검사 범위에는 한계가 있습니다. `validateR06Closeout`의 운영용 `required` 집합은 **PROJECT_CONTEXT.md와 ROADMAP.md를 제외**합니다. 두 파일의 현재 정확한 전후 바이트는 첫 closeout 테스트에서 확인하지만, closeout 검사 함수 단독으로 그 두 파일의 이후 변경까지 고정한다고 말할 수는 없습니다. 이번에는 두 파일 전체와 최신 요약을 읽었고 전체 테스트 통과 기록도 제공됐으므로 차단 사유로 보지 않습니다. 향후 해당 함수의 오류 0만으로 여섯 파일 전체의 현재 pin을 인증해서는 안 됩니다.
