**R16-I01 — 백필과 전환 사이의 실제 쓰기를 보호하는 조건이 연결됐습니다.**

위치는 `data-model-schema-migration.md`의 장소 필드 분리 예시, 백필 설명, AI 계획 프롬프트입니다. 수정된 예시는 “**백필 전에 … 선택한 보호가 유효해야 합니다**”라고 선행 조건을 명시하고, 버전 조건부 갱신으로 최신 쓰기를 덮지 않도록 합니다. 검증 이후에도 쓰기 보호를 유지하며, “**그 조건을 전환 순간까지 유지할 수 없으면 중지합니다**”라고 전환 조건을 분명히 했습니다.

최초 반례 세 가지가 각각 처리됩니다. A를 읽은 늦은 백필은 B를 덮지 않고 충돌 후 재처리합니다. 검증 뒤 들어온 구버전 쓰기는 새 표현에 반영됐는지 다시 대조하며 수렴하지 않으면 전환하지 않습니다. 새 형식의 기록을 옛 표현으로 보존할 수 없으면 구버전 복귀를 허용하지 않고 쓰기 제한·정보 보존·롤포워드를 판단합니다. 프롬프트에도 같은 요구가 들어갔습니다. 특정 DB나 이중 쓰기 방식을 보편적인 해법으로 강제하지 않아 최초 finding의 최소 수정 범위에 맞습니다.

**R16-I02 — 차단 후보의 품질과 공개 버전의 신선도가 분리됐습니다.**

위치는 `state-cache-queue.md`의 교육용 주가 fixture 설명입니다. “**`freshness_status`는 후보 품질이 아니라 기준 시점과 … `expected_refresh_at`으로 판단합니다**”라고 명시하고, 같은 차단 후보에 대해 기대 시각 전 `current`, 기대 시각 이상이며 승인 갱신을 제공하지 못한 경우 `stale`, 필요한 시각 정보가 없는 경우 `unknown`을 구분합니다.

이 설명은 최초 검토에서 대조한 11:59Z·12:01Z·기대 시각 누락 반례를 수용합니다. 마지막 정상 공개 버전의 유지, 후보 상태·이유의 별도 표시, 신선도 이유의 표시도 구분됩니다. fixture를 최신 실제 시장 값으로 확대하지 않는 경계 역시 유지됐습니다.

**R16-I03 — DB 내부의 원자적 판단과 외부 전송의 경계가 분리됐습니다.**

위치는 이벤트 설명, 재처리 3~5단계, 경쟁 반례 문단과 연습 4번입니다. “**재조회는 필요하지만, 조회 직후 상태가 바뀌는 경쟁까지 없애지는 않습니다**”라는 설명에 이어 상태·버전 판정과 결과 갱신을 함께 보호하도록 했습니다. 재처리에서는 상태 판정과 발송 결정 기록을 연결하고, 발송 결정 전 취소와 결정 이후 취소를 나눕니다.

재조회 전 취소, 재조회 후 외부 전송 전 취소, 버전 비교 뒤 최신 결과 저장이라는 세 반례가 별도로 제시됩니다. 두 번째 상황에서는 미리 정한 발송 기준 시점·취소·보상 계약과 남는 한계를 확인하고, 세 번째 상황에서는 조건부 갱신 실패 등으로 최신 결과를 보존하도록 했습니다. 외부 결과 불명과 중복 방지 계약도 유지합니다. DB 잠금을 외부 호출 동안 유지하는 방식을 모든 서비스의 해법으로 제시하지 않습니다. 설명과 연습 사이의 기존 과도한 보장도 해소됐습니다.

**R04-M05 — 예시 필드와 기준 사례 필드의 대응이 명시됐습니다.**

위치는 `data-model-schema-migration.md`의 SQL 바로 앞 문단입니다. `host_user_id`와 `host_id`, `participant_user_id`와 `participant_id`가 같은 역할을 가리킨다고 직접 연결하며, 뒤의 고유성 설명과 공동 주최자 표에도 같은 대응을 적용한다고 밝혔습니다.

SQL을 읽기 전에 대응을 확인할 수 있고, “**실제 데이터베이스 열을 바꾸거나 새 식별자를 추가하라는 지시가 아닙니다**”라는 문장으로 적용 한계를 분명히 했습니다. SQL·고유성 설명·공동 주최자 표의 기존 이름을 유지한 선택은 적절합니다. 취소 뒤 재참가를 새 행으로 보존할 경우의 UNIQUE 한계 설명도 유지되어, 이름 대응을 해결하면서 별개의 모델링 선택을 바꾸지 않았습니다.

**R16-M02 — 현재 OWASP 제목과 기존 주소가 함께 표시됐습니다.**

위치는 `frontend-backend-boundary.md`의 관련 출처 목록입니다. 링크 문구가 “**OWASP Web Frontend Security Cheat Sheet — 기존 AJAX 주소**”로 바뀌고, 2026-11-15 반환 제목임을 명시합니다. 기존 URL을 유지하면서 현재 문서의 표시 제목과 관계를 설명하므로 최초 직접 근거와 일치합니다. 출처 지도 보충은 리다이렉트 헤더가 미확인임을 유지합니다. 과거 확인 기록을 현재 제목으로 소급 교체하지 않았습니다.

**R16-M03 — 이미 확인된 공백을 앞으로 전환한다는 문구가 제거됐습니다.**

위치는 같은 원고의 마지막 출처 안내 문단입니다. 기존 PBSG-002 미래형 전환 문구 대신 세 장의 근거를 함께 관리하되 “**각 표준·제품이 직접 뒷받침하는 범위는 구분합니다**”라고 설명합니다. 이미 confirmed인 역사와 충돌하는 운영 상태 서술이 사라졌고, 새로운 공백 해소나 R16 완료를 주장하지 않습니다.

**R16-M04 — 생산자 확인과 소비자 확인의 책임이 구분됐습니다.**

위치는 `state-cache-queue.md`의 중복·재전달 설명입니다. publisher confirm은 제품 계약에 따른 브로커의 수락·보관 책임 경계, consumer acknowledgement는 소비자가 처리를 브로커에 알리는 별도 경계로 정의됩니다.

생산자 확인 뒤에도 소비자가 아직 실행하지 않았을 수 있는 경우와, 업무 완료 뒤 소비자 확인만 유실되는 경우가 모두 제시됩니다. 두 확인이 임의의 외부 알림을 정확히 한 번 성공시키지 않는다는 제한도 명시됩니다. RabbitMQ의 제품 계약을 모든 큐의 보장으로 확대하지 않아 최초 재확인 기준을 충족합니다.
