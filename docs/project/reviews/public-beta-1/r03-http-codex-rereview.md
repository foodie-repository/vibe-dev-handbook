- **현재 후보 검사가 역사 복원보다 먼저 실행됩니다.** `validateR03Inputs()`는 `validateR03Current(read)`의 오류를 먼저 확보합니다. 원고와 CONTENT_MAP이 지정된 `after` SHA가 아니면 오류가 남으므로, 옛 원고로 되돌려 역사 manifest만 통과시키는 방식으로 현재 후보를 승인할 수 없습니다.

- **rollback 거절을 실제로 구분하는 테스트가 있습니다.** 원고·지도 각각에 대해 정확한 수정 전 바이트와 수정 후 바이트에 `drift`를 추가한 값을 넣고 `R03 current patch mismatch`를 요구합니다. 역사 복원이 가능하다는 사실과 현재 후보로 허용된다는 사실을 분리합니다.

- **R02의 기존 증거와 판정 상수는 수정되지 않았습니다.** 제공된 diff는 import와 정확한 역변환 연결, 테스트의 비교 경계를 변경합니다. 과거 `BLOCKED`, 후속 결과, 고정 증거 SHA, `release_ready: false`를 새 값으로 덮어쓰지 않습니다.

여기서 **`r03PreFixBytes()` 자체는 rollback 거절기가 아니며, `validateR02Closeout()` 단독 실행도 R03 현재 후보 검사를 대신하지 않습니다.** 정확한 R03 수정 전 지도는 여전히 유효한 R02 당시 지도이므로 R02 검사에서 받아들일 수 있습니다. 현재 R03의 rollback을 거절하는 책임은 별도의 `validateR03Current()`에 있습니다. 따라서 controller의 “현재 후보 검사가 rollback을 거부한다”는 설명은 수용하지만 이를 “모든 역사 검증 함수가 R03 rollback을 거부한다”는 주장으로 확대해서는 안 됩니다.
