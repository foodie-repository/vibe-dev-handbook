**R15-I01 — Important/P1 — verbose 출력 존재를 ignore 제외 판정으로 해석합니다.**

- **위치:** `files-folders-paths.md` → 「개발자가 경로 문제를 좁히는 순서」 → 「7. Git 상태를 서로 다른 증거로 봅니다」.
- **최소 인용:** “`git check-ignore -v`에 규칙·출처·경로가 나오면 어떤 규칙이 제외했는지 알 수 있습니다.”
- **근거:** 제공된 R15 직접 근거의 Git Output 설명은 `!`로 시작하는 부정 패턴도 verbose 출력에 나타날 수 있으며, 이 경우 출력이 있어도 제외되지 않는다고 명시합니다. 제공된 `.gitignore`에도 `.env.*` 다음에 `!.env.example`이 있어 이 예외가 실제 저장소 규칙과 연결됩니다.
- **영향:** 독자는 예외로 다시 포함되는 untracked 파일을 ignored라고 잘못 분류할 수 있습니다. 이 장의 핵심 학습목표인 Git 상태와 공개·커밋 대상 판정에 직접 영향을 줍니다.
- **적용 기준:** C04, C05, C06, C08.
- **최소 수정:** “출력은 일치한 규칙과 출처를 보여 준다”로 고치고, 패턴 앞의 `!`를 확인해 제외와 재포함을 구분하도록 한두 문장을 추가합니다. tracked 파일은 기본 검사 대상에서 빠진다는 기존 설명은 유지합니다. 출력 부재 역시 정상 조회인지와 오류 여부를 구분한 뒤 해석하도록 명시하면 좋습니다.
- **재확인 기준:** 일반 제외 패턴, `!` 부정 패턴, tracked 파일, 규칙 불일치의 네 경우를 원고 설명으로 구별할 수 있어야 합니다. 실행 증거를 보충한다면 비밀값 없는 가상 파일로 검사하고 실제 `.env` 내용은 읽지 않습니다.

**R15-I02 — Important/P1 — `Stop-Process`를 애플리케이션의 정상 종료와 분명히 분리해야 합니다.**

- **위치:** `terminal-processes-ports.md` → 「포트 충돌을 안전하게 진단하는 순서」 → 「6. 소유 세션에서 정상 종료를 먼저 요청합니다」.
- **최소 인용:** “별도 PID에 신호나 종료 명령을 보낼 때도 먼저 정상 종료를 요청하고 기다립니다.” 이어서 “Windows PowerShell의 `Stop-Process`는 … 로컬 프로세스를 멈춥니다.”
- **근거:** 해당 문단은 정상 종료 요청을 설명하는 위치에 `Stop-Process`를 제시하고, 그다음 문단에서 `SIGKILL` 같은 강제 종료를 마지막 수단으로 분리합니다. 제공된 Microsoft 근거는 `Stop-Process`의 로컬 프로세스 종료를 뒷받침하지만 애플리케이션의 저장·정리·정상 shutdown을 보장하지 않습니다. 운영체제별 동작이 다르다는 일반 문장만으로 이 구체적인 차이가 충분히 전달되지 않습니다.
- **영향:** Windows 독자는 애플리케이션의 종료 기능을 사용한 것과 `Stop-Process`를 실행한 것을 같은 정상 종료 단계로 받아들일 수 있습니다. 활성 상태와 저장되지 않은 결과를 보존하려는 이 장의 절차가 약해집니다.
- **적용 기준:** C04, C05, C06.
- **최소 수정:** `Stop-Process` 소개 바로 옆에 “애플리케이션의 저장·정리 절차를 거치는 정상 종료 요청으로 간주하지 않는다”는 경계를 명시합니다. 애플리케이션 또는 관리 서비스가 제공하는 종료 절차와 OS 수준 프로세스 종료를 나눕니다. 확인 프롬프트나 `-Force` 여부도 정상 저장 보장과는 별개임을 짧게 덧붙일 수 있습니다.
- **재확인 기준:** Windows에서도 정상 shutdown 방법의 확인 → 보존·영향·승인 확인 → 필요한 OS 수준 종료 → PID·자식·포트·데이터 재확인이라는 구분이 드러나야 합니다. 실제 프로세스를 종료하는 시험은 요구하지 않습니다.

남은 한계와 비판정 사항은 다음과 같습니다.

- **DOM과 시각 증거:** HTTP 200, H1 하나, theme, 전역 overflow 없음, errors 없음은 제공된 관측 기록입니다. PNG에서 글자가 읽힌다는 사실과 같은 종류의 증거가 아닙니다. 2열 표는 DOM 폭과 전체 원문만 확인했으며 실제 표 렌더 판독을 완료했다고 하지 않습니다.
- **상호작용·접근성:** 키보드, 스크린리더, 초점 이동, 터치 조작, 1024px, 전체 사이트 탐색·검색·404는 이번 새 검증 범위 밖입니다. 색 대비 수치를 측정한 것도 아닙니다.
- **긴 자연어 프롬프트:** 실제 캡처를 연결하면 내용을 읽을 수 있지만 모바일에서는 가로 이동 부담이 큽니다. 프로젝트의 임의 하드랩 금지와 별개로 렌더 단계의 줄바꿈을 검토할 여지는 있습니다. 다만 현재 자료로 키보드 접근 실패나 영구적인 내용 손실을 입증하지 못했으므로 별도 결함으로 확정하지 않았습니다.
- **공식 출처:** reviewer는 제공된 추적 가능한 출처 기록을 읽었습니다. 공식 웹사이트를 직접 새로 열지 않았습니다. Apple의 정확한 본문 확인은 짧은 URL의 목차 반환과 분리했고, Microsoft의 authorization 배너와 읽힌 절을 전체 접근 성공으로 바꾸지 않았습니다.
- **역사와 현재성:** Python 3.14.7, npm 11.19.0, Tahoe 26, IANA 2026-08-11은 과거 확인 기록입니다. 현재 Python 표제, npm 패치 미표시, Apple 현재 페이지, IANA 갱신일 미표시로 과거 기록을 덮어쓰지 않았습니다.
- **설치 환경:** `package.json`의 npm 10.9.2 선언과 원고가 참고한 npm v11 문서는 범위가 다릅니다. 원고가 실제 프로젝트의 설치 동작을 v11 실행으로 주장하지 않으므로 이 차이만으로 finding을 만들지 않았습니다. 잠금 파일 전체·현재 설치 트리·실제 런타임 버전·깨끗한 환경 재설치는 이번 입력으로 검증하지 않았습니다.
- **실제 시스템 작업:** 경로 조회, 권한 변경, 설치, 포트 조회, 프로세스 종료를 실행하지 않았습니다. 명령 예시의 설명 검토와 실제 실행 검증을 구분합니다.
- **사례:** 모임 마감·날짜 패키지 예시는 가정으로 표시되어 있어 실제 브리프에 새 날짜 기능이 구현됐다는 주장으로 보지 않았습니다. 교육용 주가 fixture 사례도 실제 시장 데이터의 권리·가격·최신성을 주장하지 않습니다.
- **독립성:** fresh context와 읽기 전용 경계는 제공된 실행 기록과 이번 행동 범위로 확인합니다. 교차 제공자 검토를 수행한 것은 아닙니다. 세션 저장·실제 이력 복구와 사후 불변성 감사의 완료는 controller가 별도로 확인해야 합니다.

**6. 재확인 기준**

최초 응답은 현재 고정 입력에 대한 원래 결과로 보존해야 합니다. controller는 요청된 절차에 따라 이 정상 결과를 검증하고 정본에 저장한 뒤, **원고 수정 전에 별도 커밋하는 순서**를 유지해야 합니다. reviewer는 저장이나 커밋을 실행하지 않았습니다.

같은 reviewer의 후속 검토에는 다음이 필요합니다.

1. **finding별 재판정:** I01·I02·M01~M04·P-I01의 수용·부분 수용·기각과 근거를 각각 기록합니다. 준비 증거의 P-I01을 원고 오류로 합치거나, 코드 검토 PASS를 원고 PASS로 확대하지 않습니다.
2. **변경 입력 고정:** 수정한 원고의 전체 파일, 좁은 diff, 새 개별 해시, 변경된 근거·관련 문맥을 제공합니다. 원래 manifest·원래 PNG·원래 결과를 보존하고 새로운 입력과의 관계를 명시합니다.
3. **I01 재확인:** 일반 제외·부정 패턴 재포함·tracked·불일치를 원고 설명으로 구별할 수 있어야 합니다. 가상 반례를 실행했다면 명령·출력·종료 상태와 실제 실행 범위만 제공합니다.
4. **I02·M04 재확인:** Windows의 정상 shutdown과 OS 수준 종료를 명시적으로 구분하고, TCP 조회 결과에서 주소·상태·소유 PID를 선택하는 단계가 드러나야 합니다. 설치나 실제 프로세스 종료는 필요하지 않습니다.
5. **M01~M03 재확인:** 첫 용어 설명, 현재 링크와 역사 버전, 상위 경로 권한 오류의 불확실성을 수정한 위치에서 확인합니다. 역사 확인일을 소급 변경하지 않습니다.
6. **P-I01 보완:** 두 모바일 연습 표의 전체 머리글을 포함한 light/dark 보충 원본 이미지를 ID·해시·대상 원고/CSS 해시·실제 스크롤 위치와 함께 제공합니다. 변경 없는 다른 154개 이미지를 이유 없이 다시 생성할 필요는 없습니다.
7. **변경에 맞는 자동·시각 검증:** 수정된 내용에 대해 프로젝트 필수 static 검사와 관련 링크·콘텐츠 지도를 확인합니다. 공개 원고가 바뀌면 새 빌드와 필요한 영향 구간의 실제 렌더 증거를 제공하고, 이전 R14 빌드를 수정 후 출력의 증거로 재사용하지 않습니다.
8. **증거 마감:** 사후 전송·입력 불변성 감사, 결과 정본 저장, 후보 index 대조와 필요한 공개 안전 검사를 연결합니다. 같은 저장 세션의 실제 이력을 복구해 후속 검토하며 R02 승계 예외를 적용하지 않습니다.
