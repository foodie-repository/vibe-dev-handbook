# 공개 베타 M5 Codex 독립 검토 계약

- 버전: `2026-09-05-two-layer-codex`
- 대상: 공개 문서59개와 M5 R01~R26
- 정본: [review-matrix.md](review-matrix.md)의 고정 행·입력·예정 증거 경로와 이 계약을 함께 적용합니다.
- 권위: [완성 명세](../../../superpowers/specs/2026-08-12-public-beta-completion-design.md), [마스터 계획](../../../superpowers/plans/2026-08-12-public-beta-master-plan.md), `AGENTS.md`, `RULES.md`가 우선합니다. 아래 대응표는 필수 기준의 축약본이지 새 완료 계약이 아닙니다.

## 1. 상위 개정과 역사 보존

2026-09-05 사용자 결정은 공개 베타 1 M5 캠페인에 한해 2026-08-28 Claude 운영 개정의 미래 실행·완료 기준을 이 계약으로 대체합니다. 이 개정은 Claude 일반 사용, 다른 캠페인 또는 다른 역사 기록의 의미를 바꾸지 않습니다. `opus5-review-contract.md`, `claude-attempt-log.md`, `claude-preflight-*.md`, 과거 요청·결과와 `public-beta-claude-attempt-template.md`는 byte 단위 역사 기록으로 보존합니다. 이 M5 캠페인의 과거 Claude 기록은 `waived_by_owner`, 모델 호출0건, 유효 Claude 결과 없음이며 Claude PASS나 M5 완료로 해석하지 않습니다.

## 2. 역할, 권한과 두 겹 독립성

controller는 입력 고정·SHA-256 기록·요청 발행·결과 정본 저장·finding 재판정·상태 전이를 담당하며, 작성자는 검토 대상 원고의 수정만 담당합니다. 소유자는 고정 원고·기준 SHA의 최종 승인자이고 실제 사람 기술·편집·독자 검토는 수행했을 때만 선택 증거입니다.

R01~R25는 controller·작성자·이전 대화 이력과 분리된 fresh Codex reviewer가 각 행의 고정 입력 전체를 완독해 검토합니다. R26은 R01~R25 reviewer들과 분리된 fresh Codex reviewer가 R01~R25가 배정한 공개 문서59개 전체와 R01~R25의 결과·재판정·재검토, 콘텐츠 감사·source gap·시각 감사·`CONTENT_MAP.md`를 통합해 검토합니다. R01~R25에는 개별 `reviewer_independence` override를 둘 수 없고, R26만 정확히 `R01~R25 reviewer들과 분리된 fresh Codex reviewer`를 기록합니다.

reviewer의 권한은 요청서에 열거한 고정 입력을 읽는 Read-only뿐입니다. reviewer는 파일 수정·셸/Bash·Git·테스트·웹·MCP·플러그인·스킬·하위 에이전트·외부 상태를 사용하지 않습니다. reviewer는 결과를 응답으로만 반환하며 결과 파일·행렬·상태 문서를 쓰지 않습니다. controller가 요청·입력 완전성·개별/결합 SHA-256·실제 모델·reasoning effort·읽기 전용 권한과 응답 형식을 검증한 뒤에만 행렬의 정본 `*-codex-review.md` 또는 `*-codex-rereview.md` 경로에 결과를 저장합니다. controller가 저장한 정본만 M5 증거 후보이며 요청서·대화·부분 출력은 결과를 대신하지 않습니다.

계획 기본 프로필은 R01~R25 `gpt-6-astra`/`high`, R26 `gpt-6-astra`/`xhigh`입니다. 실제 실행은 사용한 Codex 모델과 reasoning effort를 결과에 기록합니다. 지정 프로필을 사용할 수 없으면 자동 fallback하지 않고 계약 개정 전까지 해당 행을 `pending`으로 둡니다.

## 3. 검토 범위와 실제 읽은 입력

각 R01~R25 reviewer는 자기 행의 공개 입력 전체를, R26 reviewer는 R01~R25의 모든 공개 입력을 합친 59개 고유 문서와 지정된 추가 입력 전체를 실제로 끝까지 읽습니다. 1M을 채우기 위한 거대한 일괄 검토나 필수 범위를 표본으로 줄이는 검토는 하지 않습니다. reviewer는 다음을 결과 첫 절에 명시합니다.

1. 요청에 적힌 입력 목록, 개별 SHA-256, 결합 SHA-256, 기준 SHA와 실제 읽은 목록의 일치 여부
2. 누락·미독·해시 불일치·범위 외 참조가 있으면 그 경로와 `BLOCKED` 사유
3. R26에서 R01~R25 전체 결과·재판정·재검토와 감사·source gap·시각 감사·`CONTENT_MAP.md`를 읽었는지 여부

입력은 다음 다섯 범주를 경로·개별 SHA-256·결합 SHA-256으로 고정합니다.

1. 이 계약, 해당 행, 기준 commit, 수용 기준, 비목표, 의존관계, 재검토 대상 finding과 실제 쟁점에 필요한 명세/계획 조항
2. 대상 원고 전체: frontmatter·본문·코드/프롬프트·표·alt·교차 링크를 생략하지 않으며 controller 요약이나 이전 PASS로 대체하지 않음
3. 주장 판단에 필요한 실제 공식·1차 출처 원문 또는 추적 가능한 출처 발췌, URL·확인일·적용 범위, source-map/source-gap 해당 행. 발췌는 원문 위치·누락 범위·필요한 예외를 추적해야 하며, 원문이 없거나 오래된 내용뿐이면 `not-confirmed`와 미게시 경계로 남김
4. 관련 중심 장·인접 문맥·용어집 정의, 소비 SVG·Mermaid 원본·alt·실제 렌더 증거. 공통 자산의 모든 소비 문맥, 접근성·테마·뷰포트 증거와 그 한계를 포함
5. 관련 콘텐츠/출처/시각 감사 행, 기존 미해결 finding·재판정·diff·검증 결과. 적용하지 않는 기준은 예외 추적과 사유를 기록

입력 완전성은 PASS의 선행 조건입니다. 입력이 하나라도 빠졌거나 실제 완독·해시·기준 SHA·모델·effort를 확인할 수 없으면 Critical·Important가 없더라도 `BLOCKED`이며 PASS로 바꾸지 않습니다.

## 5. 채점, 치명 항목과 finding 규율

9항목을 각0~2점으로 평가합니다. 핵심 장은18점 중15점 이상이면서 치명 항목0이어야 합니다. 총점으로 치명 항목이나 필수 증거 부족을 상쇄하지 않습니다. 인덱스/참고편은 역할에 맞는 근거·적용외 이유를 적고 분량이나10절 구조를 강제하지 않습니다. 정책/시각 작업 단위는 C01~C12 중 적용 기준과 원래 작업 수용 기준으로 검토하며 원고 점수표가 적용되지 않는 이유를 명시합니다.

| 9항목 | 0점 | 1점 | 2점 |
|---|---|---|---|
| 독자 문제 | 해결 문제 불명확 | 문제는 있으나 범위 넓음 | 구체적 질문/사용 상황 |
| 정확성 | 오해/혼용 가능 | 대체로 맞지만 예외 부족 | 정의/예외/용어 구분 정확 |
| 구조 | 나열 중심 | 부분 흐름 | 시스템 위치/관계 명확 |
| 쉬운 설명 | 전문용어 의존 | 비유/예시 일부 | 쉬운 정의와 정식 용어 연결 |
| 비유 한계 | 비유를 사실처럼 설명 | 한계 암시 | 맞는 지점과 깨지는 지점 명시 |
| 판단 기준 | 정보만 제공 | 일반 조언 | 선택 조건/금지 신호/검증 증거 |
| 실패 모드 | 성공 경로만 설명 | 대표 실패 일부 | 실패와 복구/예방 연결 |
| 실전 연결 | 추상 설명만 있음 | 단편 예시 | AI 작업 지시/검토 상황 연결 |
| 근거 | 출처 없음 | 출처 불명확 | 공식/1차 출처와 확인일 추적 |

치명 항목0은 보안/데이터 손실 위험 무시, PRD/두 SDD/TDD의 다른 범주 혼용, 미확인 현재 제품 기능 단정, 실제 검증 없이 AI 출력/테스트 결과를 신뢰하도록 유도함, 권리가 불명확한 이미지/장문 복제, 입력 불변성 또는 reviewer 독립성 훼손입니다. Critical/P0은 보안·데이터 손실·공개 권리·완료 조건을 깨는 오류, Important/P1은 핵심 정의·경계·학습 흐름·검증 계약의 실질 오류, Minor/P2는 공개를 막지 않는 국소 표현/시각 일관성 문제입니다. finding마다 파일 위치, 최소 인용, 관찰 근거, 영향, 최소 수정, 재확인 기준을 적습니다.

## 6. 결과 형식, 재판정과 재검토

reviewer는 자연스러운 한국어로 다음 여섯 절을 순서대로 포함한 응답만 반환합니다. 원고 재출력·전면 개작은 요청하지 않습니다. finding 하나는 위치/최소 인용·심각도·근거·최소 수정·재확인 기준을 간결하게 쓰고 같은 원인은 영향받는 모든 위치를 나열해 통합합니다. 건수 상한으로 중요한 finding을 누락하지 않으며 출력 상한/중간 종료는 불완전으로 기록하고 PASS로 인정하지 않습니다.

1. `검토 범위와 실제 읽은 입력`: 행ID·기준 SHA·전체 입력의 완독/미독·부족/범위외와 C01~C12 적용 확인
2. `판정과 건수`: `PASS`/`NEEDS CHANGES`/`BLOCKED`, Critical/Important/Minor 건수, 주요 사유, 입력 완독/불변·필수 기준·미해결 Critical/Important0 여부
3. `위치별 finding`: 안정 ID·파일:절/행·심각도·문제·입력 근거/적용 규칙·필요한 최소 수정·재확인 조건
4. `9항목 루브릭과 치명 항목`: 항목별 점수/근거·합계·치명 항목·적용외 이유
5. `미확인 사실·남은 위험·검토 한계`: 직접 확인하지 못한 외부 사실·미독/부족 입력·브라우저 증거 부족·Minor·교차 제공자 다양성 한계와 영향
6. `재확인 기준`: 수정 뒤 독립 재검토 대상/입력, 새 해시, 필요한 자동/시각 검증. 소유자 승인·`ready`·RC·M6/M7·commit·push·배포·공개 URL을 승인하거나 실행하지 않음

controller는 Critical·Important finding을 현재 원고·공식 근거·프로젝트 규칙에 대조하여 수용·부분 수용·기각으로 재판정하고 `*-adjudication.md`에 근거를 남깁니다. 의미 있는 수정 또는 입력 SHA 변경이 생기면 같은 reviewer가 영향 범위만 좁게 다시 읽고 `*-codex-rereview.md` 정본에 해소 여부를 응답으로 반환합니다. controller가 그 응답을 검증·저장하기 전에는 재판정이나 재검토 결과를 성공으로 확장하지 않습니다.

## 7. 증거 유효성, 차단과 완료 경계

증거 유효성은 실제 모델 호출 자체가 아니라 고정 입력의 완전성·해시 불변성·분리된 fresh context·읽기 전용 권한·정본 저장·C01~C12/9항목 결과·finding 재판정·필요한 재검토가 모두 연결될 때만 성립합니다. 부분 응답, 요청서만 있는 상태, 모델 또는 effort 미기록, 결과 파일을 reviewer가 직접 쓴 상태, 또는 과거 Claude 기록은 유효 Codex 독립 검토 증거가 아닙니다.

원장 `status`는 `pending`/`in_progress`/`blocked`/`done`을 유지하고 `implementation_state`, `required_review_state`, `release_ready`를 별도로 기록합니다. 차단 사유·고정 입력·마지막 실행·재개 조건을 남기되 필수 검토를 생략하지 않습니다. 고정 입력이 바뀌면 전후 SHA와 영향 행을 남기고 새 입력에 대해서만 이전 증거를 무효화해 필요한 범위를 재검토합니다. 의미 없는 표면 편집의 증거 보존도 요구/주장/데이터/실패/테스트/출처/그림 의미가 그대로라는 diff 근거가 있어야 합니다.

R01~R26 완료와 Critical/Important 0은 M5의 필요한 증거일 뿐, 59개 `ready`, 같은 RC SHA의 소유자 승인, M6/M7, commit·push·배포·공개 URL을 뜻하지 않습니다. 입력 부족·권한 위반·모델/effort 불일치·정본 저장 실패·미해소 finding은 `BLOCKED` 또는 `NEEDS CHANGES`로 남기며 controller가 임의로 PASS·M5 완료·상태 승격으로 바꾸지 않습니다. 제공자 다양성 감소는 fresh context·작성자/controller 분리·R26 분리·고정 해시·권위 조항 대응표·재판정·재검토로만 완화하며 사라진 교차 제공자 검토를 수행했다고 주장하지 않습니다.
