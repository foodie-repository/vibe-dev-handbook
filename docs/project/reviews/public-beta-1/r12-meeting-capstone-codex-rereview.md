**R12-I04 — 해소: 서버 확정과 수신 응답의 오라클**

「짧은 연습」 3번은 원래 관측만으로 A 상태와 최종 인원을 확정하지 않도록 바뀌었습니다. 별도의 통제 시험에서는 다른 변경·장애가 없고 A의 commit 직후 응답만 유실된다는 조건을 명시했습니다.

서버의 A 확정 1건·B 거절 1건, A가 받은 성공 응답 0건·전달 실패 1건, B가 받은 거절 응답 1건을 분리하고, 자기 조회와 권위 데이터로 최종 인원 3명·활성 중복 0건을 확인하도록 합니다. 통제 조건을 원래 관측에 몰래 추가하지 않습니다. **C02·C04·C08의 해당 결함은 해소됐습니다.**

**R12-I05 — 해소: 경쟁·원자성 시험 조건**

W-04 직접 증거는 시작 장벽의 의미와 한계를 설명하고 실제 DB 엔진·격리 수준·독립 연결을 사용하도록 합니다. 잠금 전략에서는 보호 경계와 두 번째 연결의 대기를, 충돌 검출 전략에서는 같은 이전 상태를 읽은 뒤 쓰기를 시도하는 동기화 지점을 예로 제시합니다. 사전 조회만 하는 결함 구현의 잘못된 교차 실행을 실제로 만들거나 검출하는지도 확인하도록 했습니다.

‘정확히 한 건 확정’은 별도 변경·저장·전달 장애가 없는 경쟁 시험의 **업무 변경** 오라클로 한정합니다. 로그나 읽기 트랜잭션까지 commit 한 건으로 제한하지 않습니다. 저장 중 실패는 첫 데이터 변경 후·commit 전에 주입하고, 해당 요청의 부분 변경 0건과 다른 요청의 정상 확정 보존을 따로 확인합니다. 직렬화 실패, 재시도 소진, commit 후 응답 유실도 분리했습니다.

추적 목록의 ‘결정적 경쟁 테스트’는 경쟁 구간 통제·관측을 명시하는 표현으로 바뀌었고 AI 작업 계약도 같은 조건을 사용합니다. 특정 잠금 방법을 모든 DB의 정답으로 강제하지 않습니다. **C02·C04·C12의 해당 결함은 해소됐습니다.**

**R12-M01 — 해소: 반복 DELETE의 의미**

W-03 수용 기준은 이미 취소된 참가에 대한 반복 DELETE가 추가 상태 변경·인원 감소·중복 취소 이력을 만들지 않고 현재 `cancelled` 상태를 안전하게 반환한다고 정합니다. 미신청 응답을 구분하고 첫 요청과 재시도의 응답이 반드시 같을 필요는 없다고 명시했습니다.

실패 사례도 반복 성공 응답 자체가 아니라 중복 인원 감소·취소 이력 생성으로 바뀌었습니다. 최초 취소·반복 취소·취소 응답 유실 후 조회의 시험 기준도 연결됐습니다. RFC 9110 §9.2.2의 의도한 효과와 응답 동일성 구분에 부합합니다.

**R12-M02 — 해소: 검증 용어의 설명**

DB commit과 Git commit은 비유의 한계 절에서 구분합니다. fixture는 가상 예시를 소개하는 문단에서, 데이터 불변식과 테스트 오라클은 성공 판정 층을 설명하기 전에 풀이합니다. rollback은 W-03의 응답 실패 설명에서, 시작 장벽은 W-04의 첫 시험 설명 바로 다음 항목에서 정의합니다.

정의가 필요한 위치 가까이에 있으며, 긴 이론이나 별도 용어집을 추가하지 않고 원래 학습 흐름을 유지했습니다. 시작 장벽의 정의가 첫 문장과 같은 문장에 있지는 않지만 곧바로 의미와 한계를 설명하므로 최초 지적의 독해 문제는 해소됐습니다.

**R12-M03 — 해소: 업무 데이터 백업과 비밀 복구**

W-05 추적의 권한 항목은 교육용 예제·소스·브라우저·로그의 실제 개인정보·비밀 제외와, 실제 운영에 필요한 업무 데이터의 보호된 백업을 분리합니다. 접근 통제·암호화·보존 정책을 명시하고, 자격 비밀과 과거 백업 해독 키를 별도 보호·복구 체계에 연결했습니다.

브리프에도 같은 구분이 있으며 실제 백업·복구 실행 성공으로 표현하지 않습니다. 필요한 업무 데이터나 과거 해독 재료를 누락하라는 의미가 사라졌습니다.

**새 finding:** 이번 수정 원고·관련 문서·검증 코드의 제공 범위에서 추가 Critical·Important·Minor finding은 없습니다. 키보드 viewport의 상단 빈 영역은 아래에 증거 한계로 기록하며, 이 정지 이미지들만으로 새로운 지속적 레이아웃 결함이나 정상 상태를 확정하지 않습니다.
