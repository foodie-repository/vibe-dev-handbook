**별도 전이·검사·렌더 코드 검토 — PASS C0/I0/M0**

제공된 코드에서 다음 책임 분리를 확인했습니다.

- `validateR17Current(read)`는 네 파일의 현재 바이트를 각각 정확한 `after` SHA와 비교합니다. 이전 버전 복귀, 임의 변경, 누락을 현재성 오류로 기록합니다.
- `r17PreFixBytes`는 경로와 전체 `after` SHA가 일치할 때만 역치환합니다. 각 치환의 유일성을 확인하고, 복원 결과가 정확한 `before` SHA인지 다시 검사합니다. 알려지지 않은 변경을 정규화해 숨기지 않습니다.
- 수정된 R17 입력 검사기는 현재성 오류를 보존한 상태에서 최초 입력의 개별·문맥·결합 해시를 확인합니다. 역사 입력이 맞는다는 이유만으로 현재 수정본의 rollback을 수용하지 않습니다.
- R16 연결은 정확히 알려진 R17 후속 변경을 되돌린 뒤 기존 R16 바이트를 비교합니다. R16 단독 검사는 R16의 역사·호환 책임이며, R17 현재 수정 보존의 책임은 별도 `validateR17Current`에 있습니다.
- text fence 테스트는 `wrap` 개수뿐 아니라 **모든 text fence 내용과 의도된 개행의 동일성**을 검사합니다. 문구 존재 테스트는 편집 회귀 방어선이며, 상태 기계나 실제 서버 동작 시험을 대신하지 않습니다.
- 렌더 스크립트는 viewport 안으로 대상을 이동한 뒤 상하 중첩 clip을 생성하고, 표는 실제 수평 이동값을 기록합니다. 글자 확대는 변경 전 계산 크기를 먼저 수집한 뒤 각 요소에 두 배 크기를 지정하므로 조상·자손에 배율이 연쇄 중복 적용되는 방식은 아닙니다.
- 새 PNG 94개를 최초 입력 검사기의 `entries: 124`가 모두 검사한다고 주장해서는 안 됩니다. 그 값은 최초 텍스트 20개·PNG 104개 묶음의 역사 검사를 뜻합니다. 이번 새 시각 묶음은 별도 매니페스트·관측 기록·전달 및 사후 감사와 연결해야 합니다.
