중요한 수정 사유는 다음 두 가지입니다.

1. **두 원고의 자연어 예시·AI 요청 계약이 화면 폭에 맞춰 줄바꿈되지 않습니다.** 모바일에서는 한 문장을 읽기 위해 여러 차례 가로 이동해야 하고, 데스크톱에서도 일부 긴 문장이 화면 밖으로 이어집니다. 끝까지 캡처했다는 사실은 이 읽기 문제를 해소하지 않습니다.
2. **디버깅 사례의 수정 후 판정이 원래 결함을 직접 검출하지 못합니다.** 수정 전 관찰에서 이미 참가 관계 한 건과 정원 불변식이 유지됐는데, 수정 후에도 “정확히 한 명만 확정”을 중심으로 제시합니다. 시간 초과 후 결과 불명과 상태 재조회라는 실제 문제를 별도로 검증해야 합니다.

**선별된 준비 6개 파일의 로컬 체크포인트 적합성은 긍정적**입니다. 입력 검사기·테스트에서 중요한 결함을 발견하지 못했고, 제공된 실행·index 증거가 그 좁은 범위를 뒷받침합니다. 캡처 스크립트는 해당 staged 6개에 포함되지 않으며, 그 Minor도 별도로 남겨야 합니다. 이 의견은 commit 실행·원고 통과·공개 승인이 아닙니다.

- **최소 인용:** 수정 전에는 “권위 데이터에는 참가 관계 한 건만 있고 정원 불변식은 유지됩니다.”라고 하면서, 수정 후에는 “회귀 테스트가 실패하고 수정 후 정확히 한 명만 확정되는지”를 확인하도록 합니다.
- **관찰·근거:** 사례의 결함은 두 사람이 모두 확정되는 정원 초과가 아니라, 경쟁 요청의 지연과 한 브라우저의 결과 불명입니다. 이미 유지되던 “한 명 확정”만 검사하는 테스트는 수정 전에도 통과할 수 있습니다. 본문에서 추가한 “결과 불명 뒤 상태 재조회가 실제로 동작”한다는 목표가 수정 전 실패·수정 후 성공의 구체적인 판정 기준으로 이어지지 않습니다.
- **영향:** AI가 데이터 불변식 테스트만 통과시키고 사용자에게 결과를 확인할 경로가 없는 상태를 회귀 방지 완료로 보고할 수 있습니다. 뒤의 운영 지연·결과 불명 비율 확인도 격리 시험에서 실제 복구 경로를 검증하는 일을 대신하지 못합니다.
- **최소 수정:** 정원 보존을 별도의 유지 조건으로 두고, 이번 결함을 직접 검출하는 기준을 추가합니다. 예를 들어 통제된 경쟁·지연 조건에서 결과 불명 표시, 쓰기 재전송 보류, 인증된 자기 참가 상태 재조회, 확인된 상태의 화면 반영을 검증합니다. 재조회 실패 시에는 불명을 유지해야 합니다. 지연 개선을 목표로 한다면 동일 조건에서 어느 측정값을 어떻게 비교할지도 명시합니다.
- **재확인 기준:** 수정 전에는 정원 불변식이 통과하더라도 이번 결함에 대한 테스트는 의도한 이유로 실패해야 합니다. 수정 후에는 그 실패가 해소되고, 별도 장애 없는 정원 경쟁의 업무 결과·활성 중복·부분 변경 조건도 유지돼야 합니다. 현재 참가 상태를 특정 과거 요청의 처리 결과와 동일시하거나, 시간 초과가 발생하면 항상 정해진 시간 안에 결과를 알 수 있다고 보장해서는 안 됩니다.
- **적용 기준:** C02·C03·C04·C06. 제공된 사례 브리프의 W-03/W-04, 「테스트 전략」의 독립 오라클, 「UI 상태와 사용자 경험」의 unknown·재조회 실패·이전 요청 종결 구분과 연결됩니다.

**R20-M02 — Minor/P2: p95와 span을 초보 독자가 해석할 짧은 정의가 부족합니다.**

- **영향:** 독자가 실제 지연 지표와 트레이스를 판단하는 단계에서 용어의 뜻을 추측해야 합니다. 특히 p95를 평균이나 최댓값으로 오해하면 성능 예산의 의미가 달라집니다.

**R20-M03 — Minor/P2: 회귀 현상과 회귀 검증, 새 결함 재현 테스트와 기존 회귀 테스트의 범위를 구분해야 합니다.**

- **재확인 기준:** 새 결함 재현 테스트의 실패→성공과 기존 회귀 테스트의 정상 유지가 각각 타당한 증거로 설명돼야 합니다.

**R20-P-M01 — Minor/P2, 캡처 코드: 실제 테마를 요청 테마와 직접 비교하지 않습니다.**
