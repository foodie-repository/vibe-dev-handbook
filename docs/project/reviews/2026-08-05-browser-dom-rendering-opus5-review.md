**P1-01 — 「사용자가 실제로 보는 DOM과 화면」(`browser-dom-rendering.md:25`)**

근거: 같은 장의 증거 표(`:87`~`:91`)는 현재 DOM과 렌더링된 화면을 서로 다른 관찰 대상으로 분리합니다. DOM은 사용자가 보는 대상이 아니라 검토자가 도구로 관찰하는 모델입니다.

독자 위험: Elements에 요소가 있으면 사용자가 본 것으로 등치해, 이 장이 경고하는 「DOM에 있으면 사용자에게 보임」(`:177`) 오해를 도입부가 먼저 강화합니다.

수정 방향: "실제 사용자에게 보이는 화면과, 개발자 도구로 확인한 현재 DOM"으로 두 대상을 분리.

**P1-02 — 「브라우저 또는 프런트엔드 코드가 그 상태에 맞는 화면을 렌더링합니다」(`:97`)**

근거: 책임 표(`:33`~`:39`)는 JavaScript를 「동작과 상태 변화」, 렌더링을 「구조와 스타일을 화면 결과로 만드는 과정」으로 구분합니다. 이 문장은 두 책임을 하나로 되돌립니다.

독자 위험: 화면이 안 바뀌면 무조건 JavaScript 문제로 좁혀 CSS·레이아웃·브라우저 경계를 건너뜁니다.

수정 방향: "프런트엔드 코드가 상태에 맞게 DOM과 스타일을 바꾸면, 브라우저가 그 결과를 화면으로 렌더링합니다"로 주체 분리.

**P2-01 — 표 열 이름 「구성요소」가 범주를 섞음 (`:33`)**: HTML·CSS·JavaScript(작성하는 자원)와 DOM(브라우저 내부 모델)·렌더링(과정)이 한 범주어 아래 놓입니다. `:41`은 설명 한계만 밝히고 범주 차이는 말하지 않습니다. 위험: 다섯 항목이 같은 종류의 부품으로 기억됩니다. 수정: 열 이름을 "이름"으로 바꾸고 자원·모델·과정 구분을 한 줄 추가.

**P2-02 — 렌더링 정의 불일치 (`:29` vs `:39`)**: 정의 문장은 "구조와 스타일과 상태", 표는 "구조와 스타일"입니다. 위험: 상태가 렌더링 입력인지 흔들립니다. 수정: 한쪽 표기로 통일.

**P2-03 — 비유 한계에 환경 차이가 없음 (`:54`~`:56`)**: 같은 문서라도 브라우저·기기·사용자 설정(글꼴 크기, 확대, 모션 감소)에 따라 결과가 달라질 수 있다는 지점이 빠져 있어, 후반의 모바일·키보드 검증 요구(`:169`)와 연결되지 않습니다. 수정: 깨지는 지점에 한 문장 추가.

**P2-04 — DOM을 「현재 배치도」로 비유 (`:45`)**: 기록물처럼 읽혀 DOM 변경이 화면 변경의 원인이라는 방향이 흐려집니다. `:56`은 가변성만 보완합니다. 수정: "무대 자체의 현재 상태이며, 여기를 바꾸면 공연이 바뀝니다" 정도로 인과 방향 명시.

**P2-05 — 예시 7단계 중 1~4단계에 확인 증거가 없음 (`:123`~`:126`)**: 5·6·7단계는 확인 대상이 분명하지만 응답 형식·데이터 변환·상태 저장·조건 분기는 어디를 보는지 없습니다. 위험: 비개발자가 혼자 수행할 수 없는 절반이 남습니다. 수정: 각 단계에 관찰 위치(응답 본문, Console, 화면 상태 표시)를 괄호로 부기.

**P2-06 — 재현과 관찰의 순서 (`:168`)**: 「화면 오류를 재현한 직후」 관찰하라고만 하고, 도구를 먼저 열어야 기록이 남는다는 전제를 밝히지 않습니다. 수정: "개발자 도구를 연 뒤 재현한다"로 순서 명시.

**P2-07 — Console 메시지의 출처 구분 없음 (`:142`)**: 확장 프로그램·제3자 스크립트가 남긴 메시지를 앱 오류로 오인할 수 있습니다. 수정: "모든 Console 메시지가 이 앱의 코드에서 나오지는 않습니다" 한 줄 추가.

**P2-08 — 개발자 도구에서의 변경 범위가 없음**: Elements에서 값을 바꿔도 서버 데이터와 배포본은 바뀌지 않는다는 사실이 어디에도 없습니다. 판단 규칙 4의 "DOM을 직접 바꿀 때"(`:167`)와 혼동될 수 있습니다. 수정: 도구 절에 한 줄 추가.

**P2-09 — 「실제 모바일 폭」의 뜻이 불명확 (`:158`, `:169`)**: 창 크기 조절인지 실제 기기인지 구분되지 않고, 실제 기기에서 Console·Network 증거를 어떻게 얻는지도 없습니다. 수정: 둘의 증거 강도가 다르다는 한 줄과 확인 범위 표기.

**P2-10 — 체크리스트에 본문이 가르치지 않은 항목 (`:207`, `:210`)**: 상태 중복은 `ui-state-and-ux.md:31`에만 있고, 포커스 확인 방법은 본문에 없습니다. 수정: 본문 근거를 넣거나 위임 대상을 항목 옆에 표시.

**P2-11 — 증상 표에 캐시·이전 자산 행이 없음 (`:151`~`:158`)**: "배포했는데 예전 화면이 보임"은 비개발자가 자주 만나는 대표 증상인데 빠져 있습니다. 수정: 행 1개 추가하고 배포 장으로 연결.

**P2-12 — 용어집과의 범위 차이 (`:97` vs `development-glossary.md:63`)**: 본문의 UI 상태는 "선택값·서버 응답·로딩·오류"까지 포함하는데 용어집 `state`는 "현재 기억하고 있는 값"으로만 정의되고, `browser`와 재렌더링 항목은 없습니다. 수정: 용어집 `state` 보강 또는 본문에 범위 차이 한 줄.
