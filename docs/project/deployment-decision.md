# 배포 도구 결정

## 결정

초기 공개 버전은 **Astro Starlight를 GitHub Pages에 정적 배포**합니다.

## 이유

- 학습 콘텐츠가 중심이므로 Markdown과 문서 내비게이션이 최우선입니다.
- 서버, 데이터베이스, 사용자 인증 없이 운영 비용과 장애 면적을 줄일 수 있습니다.
- 검색, 반응형 문서 UI, 다국어 확장, MDX 기반 확장이 가능합니다.
- Git 저장소의 변경 검토와 배포 이력을 그대로 사용할 수 있습니다.

## 비교한 대안

- Material for MkDocs: 매우 성숙하고 간단하지만 Python 도구 체계이며 향후 인터랙티브 UI 확장 경로가 상대적으로 제한적입니다.
- Docusaurus: 버전 관리와 React 생태계가 강하지만 초기 콘텐츠 사이트에는 설정과 기능 표면이 큽니다.
- 일반 웹앱: 계정과 상태 저장에는 적합하지만 현재 문제에는 운영 복잡성이 과합니다.

## 재검토 조건

다음 요구가 실제 사용자 검증으로 확인되면 별도 애플리케이션을 검토합니다.

- 로그인과 개인별 진도 저장
- 서버에서 채점하는 실습
- 유료 구독과 권한별 콘텐츠
- 사용자 업로드와 개인 프로젝트 분석
- 대규모 콘텐츠 편집을 위한 CMS

정적 문서와 웹앱은 한 시스템으로 억지로 합치지 않고, 문서 사이트를 기준 지식 계층으로 유지한 채 기능 애플리케이션을 분리합니다.
