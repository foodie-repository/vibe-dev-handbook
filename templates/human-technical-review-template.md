# 사람 기술 검토 기록

이 템플릿은 장의 개념·경계·예외·실패 위험과 검증 증거가 기술적으로 타당한지 독립적인 사람이 검토한 결과를 남깁니다. 문장이 그럴듯한지 평가하는 데 그치지 않고, 어떤 주장과 자료를 확인했으며 무엇은 확인하지 못했는지 구분합니다. 작성한 기록은 `docs/project/reviews/`에 두며, 빈 양식·검토 요청·작성자의 자체 점검·AI 검토만으로는 `technical:` 증거가 되지 않습니다.

## 검토 대상과 기준 상태

- 장 제목:
- 파일 경로:
- 확인한 버전 또는 변경 기준:
- 검토 날짜:
- 관련 다이어그램·용어집·출처 지도:
- 이번 검토의 포함 범위:
- 이번 검토의 비범위:

## 검토자와 독립성

- 익명 검토자 코드 또는 공개 가능한 이름:
- 관련 전문 영역과 검토에 적합한 이유:
- 이 원고의 작성·수정에 참여했는지:
- 이해관계 또는 독립성 한계:
- 검토 중 사용한 도구와 외부 자료:

필요하지 않은 개인정보, 회사 내부 정보, 비밀정보와 비공개 대화 전문은 저장하지 않습니다. 원고 작성에 직접 참여한 사람의 자체 점검은 유용하지만 독립 기술 검토로 기록하지 않으며, AI가 제시한 지적을 사람이 확인 없이 옮긴 결과도 사람 기술 검토로 보지 않습니다.

## 기술 흐름 재구성

원고를 읽은 뒤 다음을 검토자의 말이나 그림으로 재구성합니다.

- 이 장이 설명하는 시스템 경계와 구성요소:
- 입력·출력·상태·권한·책임의 흐름:
- 정상 경로에서 확인할 직접 증거:
- 대표 실패가 발생하는 경계:
- 복구·되돌리기·중지 조건:
- 원고의 설명에서 끊기거나 서로 충돌하는 연결:

원고를 재구성할 수 있다는 사실만으로 정확성이 증명되는 것은 아닙니다. 아래 주장별 확인과 위험 점검을 함께 수행합니다.

- 쉬운 정의가 정식 용어의 의미를 왜곡하지 않나요?
- 비슷한 용어와 책임을 서로 바꾸어 설명하지 않나요?
- 비유가 맞는 지점과 깨지는 지점이 기술 현실과 맞나요?
- 정상 경로뿐 아니라 중요한 예외·경계·실패가 포함됐나요?
- 테스트·빌드·화면·로그·배포·운영 증거가 보장하는 범위를 과장하지 않나요?
- 클라이언트 검증과 신뢰 경계 안의 서버 검증, 로컬 상태와 원격 상태를 혼동하지 않나요?
- 보안·개인정보·데이터 손실·복구·권한 위험을 누락하지 않나요?
- 특정 제품·버전·표준의 현재 동작을 확인 없이 보편적 사실로 단정하지 않나요?
- 예시와 연습이 독자에게 위험한 명령·비밀정보·운영 데이터를 요구하지 않나요?
- 출처가 실제 주장과 같은 범위를 직접 뒷받침하고 확인일이 기록됐나요?

| ID | 직접 근거 | 영향받은 절 | 심각도 | 위험과 재현·오해 경로 | 권고 조치 |

- `P0`: 보안·개인정보·데이터 손실 위험, 핵심 개념 역전, 확인하지 않은 현재 제품 기능 단정처럼 출판을 중지해야 하는 문제
- `P1`: 중요한 정의·예외·경계·증거 범위가 틀리거나 빠져 기술 검토 통과 전에 고쳐야 하는 문제
- `P2`: 핵심 정확성을 막지는 않지만 예시·용어·설명 범위를 더 명확하게 할 문제

## 결과 판정

- 전체 기술 판정: `충족` / `미충족` / `근거 부족`
- 발견된 P0·P1·P2 수:
- 해결되지 않은 P0·P1:
- 직접 확인하지 못한 주장과 이유:
- 특정 제품·표준·환경에만 적용되는 범위:
- 사람 편집 검토 또는 비개발자 독자 테스트로 넘길 문제:
- 재검토가 필요한 수정 범위:

`충족`은 검토 범위 안에서 해결되지 않은 P0·P1이 없고, 핵심 주장·예외·위험·출처 범위를 직접 확인했을 때만 선택합니다. 일부 주장이나 현재 제품 동작을 확인하지 못했으면 검토 범위를 줄여 기록하거나 `근거 부족`으로 판정합니다. 한 기술 검토자의 통과가 편집 일관성, 비개발자 이해, 접근성 또는 실제 운영 성공을 대신하지 않습니다.

## `reviewEvidence` 기록

독립적인 사람 기술 검토와 필요한 재검토가 완료되고 개인정보 경계를 확인한 뒤 다음처럼 장 frontmatter에 연결합니다.

```yaml
reviewEvidence:
  - "technical: docs/project/reviews/YYYY-MM-DD-chapter-technical-review.md"
```

검토 일정, 요청 메시지, 빈 양식, 작성자의 자체 점검, AI가 만든 검토 본문 또는 사람이 근거를 확인하지 않고 AI 지적을 승인한 기록은 사람 `technical:` 증거를 대신하지 않습니다.
