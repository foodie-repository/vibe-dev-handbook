# 사람 편집 검토 기록

이 템플릿은 장이 비개발자에게 자연스러운 한국어와 일관된 구조로 전달되는지, 용어·비유·교차 링크·학습 과제가 프로젝트 편집 원칙과 맞는지 독립적인 사람이 검토한 결과를 남깁니다. 기술 사실의 정확성은 별도 기술 검토가 담당하며, 작성한 기록은 `docs/project/reviews/`에 둡니다. 빈 양식·검토 요청·작성자의 자체 교정·AI 교정만으로는 `editorial:` 증거가 되지 않습니다.

## 검토 대상과 기준 상태

- 장 제목:
- 파일 경로:
- 확인한 버전 또는 변경 기준:
- 검토 날짜:
- 함께 확인한 용어집·관련 장·다이어그램:
- 이번 검토의 포함 범위:
- 이번 검토의 비범위:

## 검토자와 독립성

- 익명 검토자 코드 또는 공개 가능한 이름:
- 한국어 편집·교육 콘텐츠·대상 독자 관련 경험:
- 이 원고의 작성·수정에 참여했는지:
- 이해관계 또는 독립성 한계:
- 검토 중 사용한 도구:

필요하지 않은 개인정보, 회사 내부 정보와 비공개 대화 전문은 저장하지 않습니다. 작성자가 자신의 문장을 고치는 일은 필요하지만 독립 편집 검토로 세지 않으며, AI가 고친 문장을 사람이 실제 원문·규칙·맥락과 대조하지 않고 승인한 기록도 사람 편집 증거가 아닙니다.

## 첫 독해 관찰

- 제목과 첫 문단에서 예상한 독자 질문:
- 읽은 뒤 이해한 핵심 결론:
- 처음 멈추거나 다시 읽은 위치와 이유:
- 의미를 추측해야 했던 용어:
- 앞 장을 읽지 않으면 이해하기 어려운 부분:
- 예시·비유·표·다이어그램이 이해를 도운 부분:
- 길이·반복·순서 때문에 핵심을 잃은 부분:

## 장 전체 흐름 점검

- 독자 문제에서 결론까지의 순서:
- 정의에서 시스템 위치와 실제 신호로 넘어가는 연결:
- 판단 규칙에서 실패·복구·체크리스트로 이어지는 연결:
- 연습이 학습 목표를 실제 행동으로 확인하는지:
- 앞 장에서 받아오는 개념과 다음 장으로 넘기는 개념:
- 삭제하거나 합쳐도 의미가 보존되는 반복:
- 별도 장이나 용어집으로 위임해야 할 범위:

## 결과 판정

- 전체 편집 판정: `충족` / `미충족` / `근거 부족`
- 발견된 P0·P1·P2 수:
- 해결되지 않은 P0·P1:
- 기술 검토로 되돌린 제안:
- 비개발자 독자 테스트에서 확인해야 할 가설:
- 확인하지 못한 화면·링크·접근성 범위:
- 재검토가 필요한 수정 범위:

`충족`은 검토 범위 안에서 해결되지 않은 P0·P1이 없고, 용어·구조·비유 한계·교차 링크와 학습 과제가 일관될 때만 선택합니다. 편집 검토 통과는 기술 정확성, 실제 비개발자 이해, 자동 검사·빌드 또는 공개 배포 성공을 대신하지 않습니다.

## `reviewEvidence` 기록

독립적인 사람 편집 검토와 필요한 재검토가 완료되고 개인정보 경계를 확인한 뒤 다음처럼 장 frontmatter에 연결합니다.

```yaml
reviewEvidence:
  - "editorial: docs/project/reviews/YYYY-MM-DD-chapter-editorial-review.md"
```

검토 일정, 요청 메시지, 빈 양식, 작성자의 자체 교정, AI가 만든 교정 결과 또는 사람이 원문과 편집 규칙을 대조하지 않고 AI 제안을 승인한 기록은 사람 `editorial:` 증거를 대신하지 않습니다.
