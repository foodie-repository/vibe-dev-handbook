# Spec-Driven Development 작업 명세

## 1. 의도

무엇을 왜 바꾸는지, 사용자가 어떤 차이를 느껴야 하는지 씁니다.

## 2. 현재 상태

관련 파일, 기존 동작, 확인한 제약을 증거와 함께 기록합니다.

## 3. 요구 동작

정상·경계·실패 상황을 예시 또는 Given–When–Then으로 설명합니다.

## 4. 비목표

이 작업에서 바꾸지 않을 기능과 구조를 명시합니다.

## 5. 설계 선택

구성요소 책임, 인터페이스, 데이터 흐름, 선택한 대안과 버린 대안을 적습니다.

## 6. 작업 분해

각 작업은 독립 검토와 테스트가 가능한 가장 작은 단위로 나눕니다.

## 7. 검증

테스트 명령, 기대 출력, 수동 확인, 회귀 범위를 적습니다.

## 8. 운영과 복구

배포 순서, 관측 신호, 롤백 방법, 데이터 마이그레이션 영향을 적습니다.
