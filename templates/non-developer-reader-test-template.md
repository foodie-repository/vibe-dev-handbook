# 비개발자 독자 테스트 기록

이 템플릿은 독자가 글을 좋아했는지 묻는 설문이 아니라, 장의 핵심 흐름과 판단 기준을 설명 없이 재구성하고 새로운 상황에 적용할 수 있는지 관찰하는 기록입니다. 작성한 기록은 `docs/project/reviews/`에 두며, 빈 템플릿이나 테스트 요청만으로는 `reader:` 검토 증거가 되지 않습니다.

## 테스트 대상과 기준 상태

- 장 제목:
- 파일 경로:
- 확인한 버전 또는 변경 기준:
- 테스트 날짜:
- 진행자:
- 관찰자:
- 테스트 환경과 화면 크기:
- 테스트할 학습 목표:
- 테스트 전에 정한 필수 통과 기준:

## 독자 범위와 개인정보 경계

- 익명 참여자 코드:
- 목표 독자와 맞는 이유:
- 관련 사전 경험 수준:
- 이 장을 이전에 읽었는지:
- 보조 기술 또는 접근성 조건 중 관찰에 필요한 범위:

이름, 연락처, 회사 내부 정보, 프로젝트 비밀, 화면 녹화 원본처럼 검토에 필요하지 않은 개인정보와 민감정보는 저장하지 않습니다. 직접 인용은 오해가 드러나는 짧은 문장만 익명으로 기록하고, 참여자가 만든 그림이나 메모에는 비밀정보가 없는지 확인합니다.

## 진행자 안내

1. 먼저 테스트 목적과 중단 권리를 설명하고 필요한 동의를 확인합니다.
2. 독자가 원고를 읽는 동안 정답이나 용어 풀이를 제공하지 않습니다. 소리 내어 생각하기는 선택 사항이며 침묵을 실패로 해석하지 않습니다.
3. 질문은 아래 순서를 따르되 장의 학습 목표에 맞게 구체화합니다. “이 말이 맞지요?” 같은 유도 질문은 사용하지 않습니다.
4. 독자의 첫 답변과 사용한 근거를 먼저 기록한 뒤, 필요한 경우에만 같은 의미의 중립적인 재질문을 한 번 합니다.
5. 진행 중 제공한 도움은 모두 기록합니다. 도움을 받은 결과를 독립 수행으로 판정하지 않습니다.
6. 테스트 뒤에만 필요한 설명을 제공하고, 원고 문제와 독자의 사전 지식 부족을 구분하지 못한 채 독자 탓으로 결론내리지 않습니다.

## 학습 목표별 판정

테스트 전에 장 frontmatter의 `learningObjectives`를 아래 표에 옮깁니다. 결과를 본 뒤 통과 기준을 낮추거나 새 기준을 끼워 맞추지 않습니다.

| 학습 목표 | 관찰 가능한 필수 행동 | 직접 관찰한 증거 | 판정 | 제공한 도움 |
|---|---|---|---|---|
|  |  |  | `독립 수행` / `도움 후 수행` / `미수행` / `미관찰` |  |

`독립 수행`은 진행자의 개념 설명이나 정답 힌트 없이 필수 행동을 보였다는 뜻입니다. `도움 후 수행`은 개선 가능성을 보여 주지만 독립적인 독자 이해의 통과 증거로 계산하지 않습니다. `미관찰`은 실패와 다르며, 과제를 수행하지 않았거나 증거가 부족하다는 뜻입니다.

## 발견한 문제

| ID | 직접 관찰한 증거 | 영향받은 절 또는 표현 | 심각도 | 원고 문제·테스트 한계·판정 보류 | 후속 조치 |
|---|---|---|---|---|---|
| R-01 |  |  | `P0` / `P1` / `P2` |  |  |

- `P0`: 위험한 행동, 핵심 개념의 역전 또는 장의 목표 달성을 막는 문제
- `P1`: 중요한 흐름·판단·용어를 독립적으로 재구성하지 못하게 하는 문제
- `P2`: 핵심 목표를 막지는 않지만 표현, 탐색, 예시 또는 접근성을 개선할 문제

## 결과 판정

- 전체 판정: `충족` / `미충족` / `근거 부족`
- 필수 학습 목표 중 독립 수행한 항목:
- 도움 후 수행한 항목:
- 미수행한 항목:
- 미관찰한 항목:
- 발견된 P0·P1·P2 수:
- 가장 중요한 오해와 직접 증거:
- 테스트 환경이나 참여자 범위 때문에 일반화할 수 없는 점:

`충족`은 테스트 전에 정한 모든 필수 기준을 독립 수행하고 해결되지 않은 P0·P1이 없을 때만 선택합니다. 한 명의 성공은 모든 비개발자에게 이해된다는 통계적 증명이 아니며, 한 번의 실패도 독자의 능력만으로 설명하지 않습니다. 위험과 독자 범위가 넓을수록 서로 다른 배경과 접근성 조건을 가진 추가 독자 테스트가 필요합니다.

## `reviewEvidence` 기록

실제 관찰 기록이 완성되고 개인정보 경계를 확인한 뒤 다음처럼 장 frontmatter에 연결합니다.

```yaml
reviewEvidence:
  - "reader: docs/project/reviews/YYYY-MM-DD-chapter-reader-test.md"
```

테스트 일정, 참여 요청, 빈 양식, 진행자의 예상 또는 AI가 독자 역할을 연기한 결과는 실제 비개발자 독자 관찰을 대신하지 않습니다.
