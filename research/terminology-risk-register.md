# 용어 위험 등록부

확인일: 2026-08-04

| 용어 | 위험 수준 | 혼동 원인 | 편집 규칙 |
|---|---:|---|---|
| SDD | 높음 | Software Design Description와 Spec-Driven Development가 같은 약어 | 첫 등장에 두 뜻을 병기하고 문서 전체에서 풀네임 사용 |
| PRD | 중간 | 조직마다 제품 요구·시장 배경·기술 제약 범위가 다름 | 목적과 의사결정 범위를 먼저 정의 |
| TDD | 높음 | 테스트 문서 작성이나 테스트 자동화 전체로 오해 | Red–Green–Refactor 개발 규율로 설명 |
| 바이브 코딩 | 높음 | 도구·마케팅·작업 방식의 의미가 혼재 | 비개발자가 자연어 중심으로 AI와 개발하는 작업 맥락으로 한정 |
| 컨텍스트 엔지니어링 | 중간 | 프롬프트 작성의 새 이름으로 축소 | 모델에 제공할 정보·도구·메모리·검색·압축 설계로 설명 |
| 하네스 엔지니어링 | 중간 | 표준화된 단일 정의로 오해 | 에이전트의 작업 환경·도구·제약·피드백 시스템을 설계하는 실무 용어로 표시 |
| 루프 엔지니어링 | 높음 | 2026년 전후 등장한 신생 표현이며 정의가 안정되지 않음 | 업계 합의 용어가 아니라 반복 실행·평가·수정 루프를 강조하는 표현으로 분류 |
| 에이전트 | 중간 | 단순 챗봇부터 자율 실행 시스템까지 범위가 큼 | 도구를 사용해 여러 단계를 수행하는 실행 주체인지 명시 |
| 스냅샷 | 중간 | 파일, DB, VM, UI 등 대상이 다름 | 무엇의 어느 시점 상태인지 반드시 적음 |
| dry-run | 낮음 | 실제 변경이 전혀 없다고 과신 | 도구가 보장하는 부작용 범위를 확인하도록 안내 |
| fallback | 낮음 | 실패를 해결한 것으로 오해 | 품질 저하·기능 축소·데이터 차이를 함께 설명 |
| full-stack | 중간 | 모든 기술을 깊게 아는 개인이라는 과장 | 사용자 화면부터 데이터와 운영까지 연결을 이해하는 범위로 설명 |
| framework | 중간 | 라이브러리, 런타임, 플랫폼과 혼용 | 누가 제어 흐름을 소유하는지와 제공 범위를 구분 |
| architecture | 높음 | 폴더 구조나 기술 목록으로 축소 | 구성요소, 책임, 경계, 관계, 품질 속성, 트레이드오프로 정의 |
