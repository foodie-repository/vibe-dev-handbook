# R08 Git·GitHub 검토용 직접 근거

확인일2026-11-15. 공식 Git reference와 Pro Git 한국어판, GitHub Docs의 관련 본문을 읽어 요약했습니다. 과거 source-map의2026-08-04·08-13 확인 기록을 현재 확인으로 바꾸지 않습니다. 아래 요약은 원문 전체 복제나 실제 사용자 저장소·GitHub 계정 실행 증거가 아닙니다. 로컬 원고·그림·기존 렌더는 별도 고정 입력입니다.

## Git 명령의 비교·전송 경계

- [git status](https://git-scm.com/docs/git-status): DESCRIPTION은 HEAD와 index, index와 작업 트리의 차이, 무시되지 않은 untracked 경로를 구분합니다. short/branch는 상태·브랜치 정보를 요약합니다. untracked 표시 방식은 옵션과 status.showUntrackedFiles 설정으로 달라지며 --ignored는 별도입니다. 따라서 어떤 설정에서도 clean 출력 하나가 모든 파일을 증명한다고 확대하면 안 됩니다.
- [git diff](https://git-scm.com/docs/git-diff): 기본형은 index에 대한 작업 변경을 비교하고 --cached/--staged는 기본 HEAD에 대한 index를 비교합니다. HEAD가 없는 초기 브랜치의 --cached는 staged 전체를 표시합니다. commit 인수를 준 형태는 그 commit에 대한 작업 트리 변경을 봅니다. --no-index의 임의 두 경로 비교 등 다른 형식은 기초 장의 세 비교와 별개입니다.
- [git fetch](https://git-scm.com/docs/git-fetch): 원격의 refs와 필요한 객체를 가져오고 remote-tracking 참조 및 FETCH_HEAD를 갱신합니다. 원격·refspec·옵션에 따라 범위가 달라집니다. 조회처럼 보여도 로컬 참조 상태를 바꾸며, 현재 작업 브랜치 통합을 보장하지 않습니다.
- [git push](https://git-scm.com/docs/git-push): 로컬에서 원격의 브랜치·태그·다른 참조를 갱신하고 필요한 데이터를 보냅니다. 목적지는 인수·upstream/origin·설정에, 대상 참조는 refspec·설정에 영향을 받습니다. push가 검토·테스트·배포 성공을 자동 인증하지 않는다는 원고 경계에 적용합니다. 삭제·force·mirror 예시는 실행하지 않았습니다.
- [git pull](https://git-scm.com/docs/git-pull): 현재 공개 DESCRIPTION은 먼저 fetch하고 선택한 원격 브랜치를 현재 브랜치에 통합한다고 설명합니다. --ff-only를 기본으로 표시하고 --rebase·--no-rebase·--squash 및 pull.rebase/pull.squash/pull.ff 설정을 열거합니다. 원고의 merge/rebase 설명을 모든 버전·설정에서 무조건 실행되는 두 가지로 읽어도 되는지 검토해야 합니다. 현재 문서 기본값을 과거 설치 버전의 기본값으로 소급하지 않습니다.
- [gitignore](https://git-scm.com/docs/gitignore): 의도적으로 추적하지 않는 파일을 제외하는 규칙이며 이미 tracked인 파일에는 적용되지 않습니다. .gitignore 외에도 info/exclude와 core.excludesFile 등의 출처가 있습니다. 비밀 삭제·과거 이력 삭제·안전 보증으로 사용할 수 없습니다.

## 분산 저장·스냅샷·브랜치

[Pro Git 한국어판 목차](https://git-scm.com/book/ko/v2)에서 실제 아래 세 본문으로 이동해 읽었습니다. 목차만 확인한 것을 원문 검토로 계산하지 않습니다.

- [버전 관리란](https://git-scm.com/book/ko/v2/시작하기-버전-관리란%3F): 시간에 따른 파일 변화와 과거 상태 비교·복구, 로컬·중앙집중·분산 방식을 구분합니다. 분산 저장소의 이력 복제 설명은 Git 밖의 데이터베이스·계정·업로드 파일까지 보호하는 완전한 백업 증거가 아닙니다.
- [Git 기초](https://git-scm.com/book/ko/v2/시작하기-Git-기초): 스냅샷, 로컬 작업, working tree·staging area/index·repository와 committed/modified/staged를 설명합니다. 본문에 있는 손실 불가능처럼 읽힐 수 있는 강한 수사는 일반 안전 보증으로 인용하지 않습니다. 네트워크 없는 로컬 commit과 원격 공유를 구분하는 안정된 개념에만 적용합니다.
- [브랜치란 무엇인가](https://git-scm.com/book/ko/v2/Git-브랜치-브랜치란-무엇인가): commit의 스냅샷·메타데이터·부모 관계, 이동하는 branch와 HEAD, checkout에 따른 작업 파일 변화를 설명합니다. 예제 master 이름·40자리 SHA-1·구현 바이트 수를 모든 현재 저장소의 고정 사양으로 일반화하지 않습니다. 그림이나 예문을 핸드북에 복제하지 않았습니다.

## GitHub 협업과 자동화

- [Pull requests](https://docs.github.com/en/pull-requests/reference/pull-requests): 변경 병합을 제안하고 논의·검토하는 GitHub 기능입니다. conversation·commits·checks·files changed 등의 문맥과 승인·병합 조건을 구분합니다. draft PR은 병합할 수 없다는 별도 상태도 설명합니다. Git 자체 명령·타 호스팅 제품·특정 요금제 권한으로 확대하지 않습니다.
- [Understanding GitHub Actions](https://docs.github.com/en/actions/get-started/understand-github-actions): 이벤트에서 workflow가 실행되고 jobs·steps·runner를 통해 build/test/deploy 등을 자동화할 수 있다고 설명합니다. 설정 존재·실제 실행·성공·사용자 흐름은 다른 증거입니다. 계정별 보호 규칙·요금제·실제 UI·실행 성공은 이번 자료 확인 범위가 아닙니다.
