# R12 모임 캡스톤의 근거 적용 범위

2026-11-15 이번 연속 실행에서 이미 확인한 공식 근거를 해당 주장 범위에서 재사용합니다. 아래 연결 문서의 확인일·실제 읽은 절·접근 실패·일반화 금지선을 그대로 유지하고, R12 때문에 모든 URL을 다시 조회한 것으로 기록하지 않습니다. 새로 확인한 것은 HTTP 반복 요청의 의미에 관한 아래 한 절입니다. 기존8월 확인과 제품 예시는 역사로 보존하며 이 문서는 원고 PASS나 실제 모임 앱 구현·운영 성공이 아닙니다.

## 같은 실행의 유효 근거 재사용

- [R04 API·데이터베이스·인증](r04-api-data-auth-2026-11-15.md)의 OAS3.2.0 요청·응답·보안 선언, OWASP 요청별/객체별 인가·인증·로그 제외 값, PostgreSQL18 트랜잭션·격리·제약 관련 절을 W-01~W-05에 적용합니다. 단순 트랜잭션 선언만으로 다중 행 정원 불변식을 보장하지 않으며 실제 잠금/격리/재시도 전략과 직접 데이터 오라클이 필요합니다. 부분 고유 인덱스와 다른 행을 참조하는 CHECK의 한계를 구분합니다.
- [R06 요구·설계](r06-prd-sdd-tdd-2026-11-15.md)의 SWEBOK 공식 목차는 요구·설계·구현·테스트·운영을 나누는 교육 범위의 근거입니다. 전문이나 W-01~W-05 양식의 국제 표준 의무가 아닙니다. Spec Kit의 제품 흐름은 R12의 채택 근거로 사용하지 않습니다.
- [R08 Git](r08-git-github-2026-11-15.md)의 status/diff·Pro Git 본문은 작업 트리·index·로컬 commit·원격 공유의 차이를 뒷받침합니다. 명령 버전의 현재 기본값이나 GitHub 계정 기능을 모임 앱의 실행 증거로 일반화하지 않습니다.
- [R09 빌드·배포](r09-build-deploy-2026-11-15.md)의 Astro/GitHub Pages 설명은 소스·정적 아티팩트·배포 환경·공개 확인을 구분하는 문맥에만 적용합니다. 정적 Pages가 모임 앱의 서버·DB를 제공한다거나 이 캡스톤이 해당 배포 구조를 채택했다고 해석하지 않습니다. 제품 조합의 현재 적합성·비용·지원은 not-confirmed입니다.
- [R10 운영](r10-operations-2026-11-15.md)의 OWASP 로그 제외, NIST 복구 전후 무결성 확인, CISA 분리 백업·복원 시험 관련 절을 W-05에 적용합니다. 특정 제품 복원·실제 운영 데이터·현재 계약·법적 적합성은 검증하지 않았습니다. 로그·백업의 존재와 격리 복원 뒤 업무 성공은 다른 증거입니다.

## 새로 확인한 HTTP 반복 요청 의미

공식 [RFC9110 §9.2.2](https://www.rfc-editor.org/rfc/rfc9110#section-9.2.2)의 관련 본문을2026-11-15에 읽었습니다. 짧은 직접 발췌: “the response might differ”. PUT·DELETE·safe method의 멱등성은 같은 요청을 반복했을 때 서버에 의도한 효과가 같다는 의미이며 응답이 항상 같다는 의미가 아닙니다. 비멱등 메서드는 실제 요청 의미가 멱등임을 알거나 원 요청이 적용되지 않았다는 별도 근거 없이 자동 재시도하지 않도록 설명합니다. W-03의 이미 취소된 참가 처리·응답 유실·중복 방지와 연습 문제의 서버 확정/클라이언트 응답 구분을 검토하는 직접 근거입니다. 실제 API의 응답 코드나 데이터 상태는 구현 계약과 시험으로 별도 확인해야 합니다.

## 남은 경계

Supabase·Vercel·Codex Sites의2026-08-13 예시 날짜를 현재 기능 확인일로 바꾸지 않습니다. current-tool-mapping의 제품 표와 PBSG-020의 역사적 미확인 범위도 자동 해소하지 않습니다. 웹 화면의 현재 기능이나 실제 앱/DB·배포·복원 실행은 not-confirmed입니다. 이번 검토는 교육용 원고가 책임·수용 기준·오라클·승인 경계를 일관되게 설명하는지 판단합니다. HTTP 새 추출은 접근 실패가 없었으며 원문 전체 완독이나 다른 절의 새 확인으로 확대하지 않습니다.
