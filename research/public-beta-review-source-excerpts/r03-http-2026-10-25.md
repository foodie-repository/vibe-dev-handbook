# R03 HTTP 직접 근거 — 2026-10-25

확인일은 접근일이며 발행일이 아닙니다. 과거 source-map의 확인일·실패·R01/R02 근거는 수정하지 않습니다. 이 자료는 공식 문서의 아래 좁은 주장과 예외만 확인한 것이며 설치 브라우저·실제 모임 API의 구현 성공 또는 공개 URL 검증은 아닙니다. 원문 전체를 복제하지 않고 지정 절·짧은 인용과 재서술로 추적합니다. 필요한 다른 주장이나 범위가 이 자료로 입증되지 않으면 reviewer가 미확인으로 남겨야 합니다.

## RFC 9110 — 메시지·안전성·멱등성

- URL: https://www.rfc-editor.org/rfc/rfc9110.html
- 상태: IETF Standards Track RFC 9110, June 2022. 번호가 고정된 표준이며 최신 HTTP 구현 전체를 뜻하지 않습니다.
- 확인 위치: §9.1의 메서드 표, §9.2.1~9.2.2의 정의·반복·예외, §15.3.5의204. 이외 요청/응답·HTTPS 기본은 R02의2026-10-15 발췌에서 기존 확인일 그대로 재사용할 수 있습니다.
- 원문 최소 발췌: “the intended effect on the server”, “though the response might differ”, “SHOULD NOT automatically retry”, “cannot contain content or trailers”.
- 재서술: 안전성은 클라이언트가 의도한 변경을 요청하지 않는 의미이고 로그 등 부수 효과0의 보장이 아닙니다. PUT·DELETE·안전한 메서드의 멱등성은 반복의 의도된 효과에 관한 것이며 응답 동일성을 요구하지 않습니다. 비멱등 요청의 자동 재시도는 실제 멱등 의미 또는 최초 미적용을 알 수 있을 때라는 예외를 구분합니다.204는 성공했지만 응답 내용·trailer가 없는 상태입니다.
- 경계: 업무별409/422 선택, POST의 중복 방지 저장·유효기간·동시성 구현, 현재 상태 조회 경로는 RFC에서 자동 도출하지 않습니다. PATCH·429 등 RFC9110 외 정의의 세부는 이 발췌만으로 새로 확인한 것으로 표시하지 않습니다.

## WHATWG Fetch — CORS

- URL: https://fetch.spec.whatwg.org/#http-cors-protocol
- 상태: Living Standard, 페이지 표시는 Last Updated19 October2026. 해당 좁은 절을2026-10-25에 확인했습니다.
- 확인 위치: §3.3~3.3.3 response sharing·OPTIONS; §4.1 HTTP fetch의 preflight 실패 반환→network fetch→CORS check 순서.
- 원문 최소 발췌: “allows responses to declare they can be shared with other origins”, “It uses OPTIONS as method”, “return a network error”.
- 재서술: CORS는 출처 간 응답 공유를 opt-in하는 HTTP 위의 규칙입니다. 필요한 사전 요청이 실패하면 본 요청으로 진행하지 않지만, network fetch 뒤 CORS check에서 실패하는 흐름도 있어 응답 사용 불가가 서버 미처리의 증거는 아닙니다.
- 경계: 인증·인가·서버 간 요청 차단으로 확대하지 않습니다. credential·캐시·리디렉션 등 전체 알고리즘을 이 요약으로 대체하지 않으며 단순 요청의 부작용 안전성을 보장하지 않습니다.

## W3C Mixed Content

- URL: https://www.w3.org/TR/mixed-content/
- 상태: Candidate Recommendation Draft23 February2023. 완성 Recommendation으로 표현하지 않습니다.
- 확인 위치: §3.1 Upgradeable Content, §3.2 Blockable Content, §4.4 요청·§4.5 응답 차단, §4.1 Upgrade a mixed content request to a potentially trustworthy URL.
- 원문 최소 발췌: “Upgradeable Content”, “Blockable Content”, “Return blocked”.
- 재서술: 이미지·오디오·비디오 등 일부 자원과 스크립트 등 blockable 자원을 구분합니다. upgradeable은 안전하다는 뜻이 아닙니다. HTTP 자원의 HTTPS 업그레이드와 실패·차단을 구분하고 최상위 navigation 등 예외가 있습니다.
- 경계: 모든 혼합 콘텐츠·브라우저 버전의 경고 UI나 차단 방식이 같다는 주장이 아닙니다. 설치 브라우저에서 해당 정책을 실행한 검증은 없습니다.

## Chrome Network

- URL: https://developer.chrome.com/docs/devtools/network/
- 상태: 날짜 미고정 제품 문서,2026-10-25 접근.
- 확인 위치: When to use the Network panel, Log network activity, Show more information, Inspect a resource's details.
- 원문 최소 발췌: “Status: The HTTP response code.”, “Time: How long the request took.”, “Use this tab to inspect HTTP headers.”
- 재서술: Network 열에서 응답 코드·소요 시간을 보고 URL과 개별 Headers/Response를 열람할 수 있습니다. 패널이 열려 있는 동안 활동을 기록하며 재현 뒤 개별 요청과 응답을 확인하는 용도입니다.
- 경계: 다른 브라우저의 이름·UI가 동일하다는 뜻이 아니며, 한 요청 관측은 서버 인가·DB commit·모든 실패 조건 검증이 아닙니다.
