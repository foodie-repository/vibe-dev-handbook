# 모임 일정·참가 신청 웹앱 사례 브리프

## 독자 문제

주최자와 참가자의 행동이 화면·API·데이터·권한·운영 책임을 어떻게 통과하는지 설명합니다.

## 역할

- 비로그인 방문자: 공개 모임 조회
- 참가자: 자신의 참가 신청·취소
- 주최자: 자신이 만든 모임 생성·수정·취소·마감과 참가 현황 조회

## 상태 모델

- event.status: open | closed | cancelled
- registration.status: confirmed | cancelled
- event.version: 동시 수정 감지용 정수

새 모임은 open이며 주최자는 open→closed, open/closed→cancelled로 전환할 수 있습니다. 재개는 비목표이므로 closed→open과 cancelled의 상태·정보·정원 변경을 거절합니다. 만석은 인원과 정원의 판정이고 자동 closed 저장이 아닙니다. open의 빈자리·정원 증가만 새 참가를 허용하며 수동 closed는 그대로 유지합니다. closed의 소유자 정보·정원 수정은 버전·정원 하한을 지켜도 재개하지 않습니다.

모임 취소 때 기존 참가 행은 이력으로 보존하고 event.cancelled를 우선 안내하여 confirmed 기록을 유효 참가로 표시하지 않습니다. 참가자는 세 모임 상태 모두에서 자신의 confirmed를 cancelled로 바꿀 수 있고, 재참가는 open·정원 여유·활성 고유성 조건에서만 확정합니다. 반복 자기 취소는 현재 cancelled를 안전하게 반환하되 추가 인원 감소·취소 이력을 만들지 않습니다. 모임 취소와 참가가 경쟁하면 참가 확정 후 모임 취소로 이력만 남거나, 취소가 먼저 확정되어 참가가 거절됩니다. 같은 모임의 일관성 경계에서 조정합니다.

## 데이터 관계

- users 1:N events via events.host_id
- users N:M events via registrations
- registrations(event_id, participant_id)는 활성 참가 기준 중복을 허용하지 않음

## 수직 조각

- W-01 GET /events/:eventId 공개 조회
- W-02 POST /events와 PATCH /events/:eventId 주최자 소유권, 주최자 전용 GET /events/:eventId/registrations는 현재 주체와 events.host_id가 일치할 때만 해당 event_id의 participant_id·registration.status를 반환
- W-03 POST /events/:eventId/registrations, DELETE와 GET /events/:eventId/registrations/me. 자기 조회는 인증 주체의 관계만 읽고 모임 상태와 not_registered/confirmed/cancelled를 반환하며 다른 사람이나 전체 참가 목록은 반환하지 않습니다. not_registered는 조회 응답 분류이지 저장 상태가 아닙니다. 조회 실패는 결과 불명으로 남기고 읽기를 재시도하며 POST를 무조건 재전송하지 않습니다.
- W-04 capacity·status·중복·동시 요청을 선택한 데이터 일관성 전략과 하나의 트랜잭션에서 판정. 실제 DB의 독립 연결과 경쟁 구간 통제/관측을 사용하고 출발 장벽만으로 교차 실행을 증명하지 않습니다. 별도 장애 없는 두 요청 경쟁, 저장 중 실패의 해당 요청 부분 변경0/타 요청 정상 확정 보존, 재시도 소진과 commit 뒤 응답 유실을 분리합니다.
- W-05 비밀·환경·로그·백업·복원·공개 흐름 인수

## 완료 판정 층

- 화면 성공: 사용자가 로딩·완료·거절·결과 불명을 구분하고 다음 행동을 찾습니다.
- 업무 성공: 방문자·참가자·주최자의 허용된 행동이 계약대로 끝납니다.
- 데이터 불변식 성공: 활성 중복 0건, `confirmed <= capacity`, 소유권 밖 변경 0건을 권위 데이터에서 확인합니다.
- 운영 성공: 배포 버전과 안전한 신호를 확인하고 격리 복원 뒤 핵심 흐름을 다시 검증합니다.

## 비목표

교육용 fixture·로그·예제에는 실제 개인정보·비밀을 넣지 않습니다. 실제 운영에 필요한 업무 데이터의 백업은 승인된 접근 통제·암호화·보존 정책에 따르고, 자격 비밀과 과거 백업을 해독할 키는 별도의 보호·복구 체계로 관리해야 합니다. 이 브리프는 그 실행 성공을 주장하지 않습니다.

결제, 환불, 채팅, 댓글, 알림, 지도, 캘린더, 반복 모임, 대기 명단, 추천, 공개 검색, 파일 업로드, 운영자 신고 시스템을 포함하지 않습니다.
