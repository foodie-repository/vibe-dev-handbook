# 독자 페르소나와 사용 상황

## 1. 데이터 분석가형 빌더

- 강점: 데이터 흐름, 지표, SQL, 검증 사고에 익숙함
- 낯선 점: 웹 런타임, 프런트 상태, 인증, 배포, Git 협업
- 필요한 연결: 데이터 파이프라인과 요청·응답, 스키마·마이그레이션의 공통점과 차이

## 2. 제품·업무 도메인 전문가

- 강점: 문제와 업무 규칙을 잘 앎
- 낯선 점: 요구사항을 모호하지 않게 쓰는 법, 기술 제약, 실패 경로
- 필요한 연결: PRD에서 수용 기준과 예외 규칙으로 내려가는 흐름

## 3. 창작·1인 사업자형 빌더

- 강점: 사용자 경험과 아이디어가 분명함
- 낯선 점: 개인정보, 결제, 운영, 복구 책임
- 필요한 연결: 프로토타입과 운영 서비스의 책임 차이

## 공통 불안

- AI 로그의 용어가 낯설어 작업을 중단하거나 무조건 승인함
- 화면이 보이면 완성됐다고 생각함
- 실패가 나면 원인을 좁히지 않고 프롬프트를 크게 바꿈
- Git을 백업 서비스로만 이해함
- 프레임워크 이름을 아키텍처로 착각함

## 공통 성공 신호

독자가 기술 이름을 많이 외우는 것이 아니라 다음 질문을 하기 시작하면 성공입니다.

- 이 구성요소의 책임과 경계는 무엇인가요?
- 입력과 출력 형식은 무엇인가요?
- 실패하면 사용자와 데이터에 어떤 일이 생기나요?
- 이 선택을 검증할 테스트와 로그는 무엇인가요?
- 되돌릴 수 있는 가장 작은 변경 단위인가요?
