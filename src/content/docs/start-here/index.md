이 핸드북은 프로그래밍 언어 문법서나 특정 AI 도구의 사용 설명서가 아닙니다. **AI와 함께 개발할 때 필요한 소프트웨어공학의 최소 공통 기반**을 비개발자의 언어로 다시 구성합니다.

## 어떤 문서부터 읽을까요?

1. [왜 이 가이드가 필요한가](why-this-guide/) — 화면 동작과 운영 가능한 소프트웨어가 왜 다른지, 이 핸드북이 무엇을 약속하고 무엇을 대신하지 않는지 확인합니다.
2. [학습 경로](learning-paths/) — 빠른 지도·13장 Build Track·Deep Track 중 자신의 목적에 맞는 순서를 고릅니다.
3. [이 가이드를 사용하는 법](how-to-use-this-guide/) — 처음부터 따라가는 방법과 막힌 문제부터 검색하는 방법을 실제 학습 습관으로 옮깁니다.

세 문서를 모두 읽기 어려우면 현재 상황에 맞춰 시작해도 됩니다. 전체 흐름이 낯설면 학습 경로로, 작업 중 오류나 낯선 용어가 급하면 사용하는 법의 검색 절로 이동하세요.

## 학습의 성공 기준

용어를 많이 외웠는지는 중요하지 않습니다. 다음 질문을 스스로 던질 수 있으면 제대로 배우고 있는 것입니다.

- 이 기능은 시스템의 어느 구성요소가 책임져야 하나요?
- 입력과 출력의 약속은 무엇인가요?
- 정상 경로뿐 아니라 실패 경로는 무엇인가요?
- 무엇이 바뀌었고, 어떻게 되돌릴 수 있나요?
- 테스트와 로그가 실제 요구사항을 증명하나요?
- 운영 환경에서만 생기는 차이는 무엇인가요?

이 질문들은 특정 프레임워크가 바뀌어도 오래 남습니다.

## 다음 이동

순서를 정했다면 [1. 개발자 사고와 소프트웨어](../01-mental-models/)에서 화면을 시스템으로 보는 법부터 시작하세요. 당장 해결할 문제가 있다면 사이트 검색과 [참고편](../reference/)을 함께 사용하되, 체크 표시나 검색 결과를 실제 테스트·브라우저·데이터·배포 증거로 착각하지 마세요.
