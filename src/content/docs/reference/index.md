이 참고편은 공식 Build Track의 순서를 다시 나열하는 곳이 아니라, 작업 중 생긴 질문에서 필요한 정의·관계·점검 기준을 검색해 다시 본문으로 돌아가는 곳입니다. 검색 결과의 제목과 설명을 보고 아래 자료의 역할을 구분해 사용하세요.

## 무엇을 찾을 때 어디로 가나요?

1. [개발 용어집](development-glossary/) — 웹·데이터·Git·품질·운영의 기본 용어를 쉬운 정의와 시스템 관계로 찾습니다.
2. [에이전트 출력 용어집](agent-output-glossary/) — snapshot·dry-run·fallback처럼 작업 로그에 나타나는 말을 부작용과 확인 질문까지 함께 읽습니다.
3. [방법론 관계 지도](methodology-map/) — PRD·두 SDD·TDD·SDLC·CI/CD와 AI 실무 표현의 범주·순서·겹침을 구분합니다.
4. [실전 체크리스트](checklists/) — 시작·변경·검토·배포·운영에서 빠뜨린 질문을 점검합니다.
5. [날짜 있는 현재 도구 매핑](current-tool-mapping/) — 오래 유지되는 책임과 특정 날짜에 확인한 제품 기능을 구분합니다. 기능이 바뀌면 이 자료를 먼저 확인한 뒤, 그 기능을 사용하는 장의 설명·실습·권한 조건도 함께 확인합니다.

용어 정의는 도구와 문맥에 따라 달라질 수 있습니다. 특히 스냅샷, 샌드박스, fallback, SDD처럼 여러 뜻이 있는 단어는 **무엇을 대상으로 어떤 보장을 하는지** 함께 확인하세요.

체크 표시와 검색 결과는 실제 실행·검증·승인·배포·공개 완료의 증거가 아닙니다. 현재 도구 매핑도 특정 제품의 기능을 핵심 개념의 정의로 바꾸지 않으며, 확인일과 공식 근거를 다시 확인하는 교체 가능한 참고 자료입니다.

## 다음 이동

정의를 확인했다면 검색 결과가 가리키는 본문 장으로 돌아가 실제 맥락과 판단 규칙을 읽으세요. 처음부터 학습 순서를 잡으려면 [공식 학습 경로](../start-here/learning-paths/)를 사용하고, 전체 흐름을 프로젝트로 연결하려면 [12. 사례와 캡스톤](../12-case-studies/)으로 이동하세요.
