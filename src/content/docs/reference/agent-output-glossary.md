같은 단어도 도구에 따라 범위가 다릅니다. 이 용어집은 특정 제품의 버튼 이름보다 오래 유지되는 뜻을 먼저 설명합니다. 각 행에서 **무슨 행동·상태인지, 어떤 부작용이 가능한지, 무엇을 증거로 확인할지**를 함께 읽으세요.

`plan mode`, `workspace-write`, `read-only`처럼 제품이 정책 이름으로 쓰는 표현은 일반 개념과 완전히 같지 않습니다. 현재 제품별 의미와 확인일은 [현재 도구와 역할 매핑](../current-tool-mapping/)에서 다시 확인해야 합니다.

## 작업 상태와 도구

| 용어 | 행동·상태 | 가능한 부작용 | 확인 질문 |
|---|---|---|---|
| **status update** | 에이전트가 지금 확인한 사실과 다음 행동을 중간에 요약한 메시지 | 오래된 요약을 완료 증거처럼 믿으면 실제 상태와 판단이 어긋날 수 있습니다. | 실제 파일·명령·화면 증거가 뒤따랐나요? |
| **tool call** | 파일·터미널·브라우저·외부 API 같은 도구에 구체적인 행동을 요청하는 단계 | 읽기뿐 아니라 파일 변경, 프로세스 실행, 네트워크 요청, 외부 쓰기가 일어날 수 있습니다. | 전체 입력·대상·권한과 실제 반환값을 확인했나요? |
| **plan mode** | 제품이 변경보다 조사·계획을 우선하도록 행동을 제한하는 정책 이름 | 제품·버전·호스트에 따라 읽기, 명령 실행, 임시 파일, 네트워크 허용 범위가 다를 수 있습니다. | 어느 제품의 어떤 정책이며 공식 문서 확인일은 언제인가요? |
| **blocked** | 필요한 입력·권한·외부 상태가 없어 현재 범위에서 진행할 수 없다는 상태 | 너무 일찍 선언하면 가능한 읽기·부분 검증·안전한 대안을 놓칠 수 있습니다. | 무엇이 바뀌면 재개되며 안전한 대안은 어디까지 확인했나요? |

## 변경과 상태

| 용어 | 행동·상태 | 가능한 부작용 | 확인 질문 |
|---|---|---|---|
| **snapshot** | 파일·UI·DB·가상환경 등의 특정 시점 상태를 저장하거나 표현한 것입니다. | 저장 범위에 따라 민감정보가 복제되고, 비교용 캡처를 복구본으로 오해할 수 있습니다. | 무엇의 어느 시점이며 비교용인가요, 실제 복구용인가요? |
| **checkpoint** | 긴 작업에서 다시 시작하거나 검토할 수 있게 남긴 중간 지점입니다. | 불완전한 상태를 안전한 복원점으로 오해하거나 필요한 외부 상태를 빠뜨릴 수 있습니다. | 자동 저장, Git 커밋, 문서 기록 중 무엇이며 어디까지 복원되나요? |
| **diff** | 두 상태 사이의 추가·수정·삭제·이름·권한 차이를 표현합니다. | 일부 보기나 잘린 출력만 보면 삭제, 바이너리, untracked 파일을 놓칠 수 있습니다. | 비교 기준 두 개와 전체 변경 범위를 확인했나요? |
| **patch** | 변경 차이를 다른 기준 상태에 적용할 수 있는 형식으로 표현합니다. | 기준 버전이 다르면 충돌하거나 문맥상 틀린 위치에 적용될 수 있습니다. | 어떤 기준 커밋용이며 적용 후 diff와 검증 결과가 무엇인가요? |
| **working tree** | 현재 작업 폴더에서 체크아웃된 파일과 커밋되지 않은 변경 상태입니다. | 에이전트 변경이 기존 사용자 변경과 섞이거나 덮어쓸 수 있습니다. | 시작 전 status와 기존 변경의 소유 범위를 확인했나요? |
| **staged** | 다음 Git 커밋에 포함하도록 선택된 변경 상태입니다. | 파일 전체가 아니라 일부만 들어가거나 무관한 변경이 함께 포함될 수 있습니다. | `git diff --cached`가 한 목적의 완전한 변경인가요? |
| **repository** | Git이 커밋·브랜치·태그와 파일 이력을 관리하는 경계입니다. | 잘못된 저장소나 상위 저장소에서 명령하면 의도 밖 파일에 영향을 줄 수 있습니다. | 현재 최상위 경로와 원격이 의도한 저장소인가요? |
| **tracked / untracked** | Git이 이미 이력 대상으로 아는 파일 / 작업 폴더에는 있지만 아직 모르는 파일 상태입니다. | 기본 diff만 보면 untracked 파일 내용을 놓칠 수 있습니다. | status와 새 파일 내용을 각각 확인했나요? |
| **ignored** | ignore 규칙에 따라 기본 상태 표시와 추가 대상에서 제외된 상태입니다. | 비밀 보관 기능이 아니며 이미 추적된 파일과 과거 이력을 제거하지 않습니다. | 규칙의 출처와 이미 추적 중인지 확인했나요? |
| **commit** | 스테이징한 프로젝트 상태와 설명·부모 관계를 로컬 이력에 기록합니다. | 잘못 선별하면 무관한 변경이 고정되고, 테스트·백업·원격 공유를 했다고 오해할 수 있습니다. | 한 목적의 staged diff와 검증 결과를 확인했나요? |
| **HEAD** | 현재 체크아웃한 브랜치 또는 커밋을 가리키는 Git 위치입니다. | detached 상태나 예상과 다른 기준에서 작업하면 후속 커밋·병합 경로가 달라집니다. | 브랜치 이름과 기준 커밋이 예상과 일치하나요? |
| **dirty / clean** | 정한 기준에서 커밋되지 않은 변경이 있음 / 없음인 상태입니다. | ignored 파일을 제외한 clean을 모든 로컬 상태가 없다는 뜻으로 오해할 수 있습니다. | untracked·ignored 포함 여부와 사용한 명령을 밝혔나요? |

## 실행 전 예측과 대안

| 용어 | 행동·상태 | 가능한 부작용 | 확인 질문 |
|---|---|---|---|
| **dry-run** | 실제 적용 대신 도구가 예상 행동을 계산하거나 보여주는 실행 방식입니다. | 구현에 따라 파일만 막고 네트워크 조회·인증·잠금·외부 검증은 수행할 수 있습니다. | 이 도구가 막는 부작용은 파일·프로세스·네트워크·외부 API 중 어디까지인가요? |
| **preview** | 적용·병합·배포 전에 예상 결과를 제한된 환경에서 보여주는 상태입니다. | 운영 데이터·권한·트래픽·환경과 달라 실제 결과를 보장하지 않습니다. | 운영과 다른 입력·설정·권한은 무엇인가요? |
| **plan** | 수행할 단계, 변경 범위, 결정 지점과 검증을 제안한 것입니다. | 실행되지 않은 계획을 구현이나 검증 완료로 오해할 수 있습니다. | 파일·수용 기준·위험·검증 명령이 있고 실제 실행 여부가 구분되나요? |
| **fallback** | 주 경로가 실패하거나 불가할 때 선택하는 대체 경로입니다. | 기능·정확도·속도·보안·데이터 최신성이 낮아질 수 있습니다. | 전환 조건과 저하 범위를 사용자에게 드러내며 원래 경로로 돌아가는 조건이 있나요? |
| **graceful degradation** | 일부 기능이 실패해도 핵심 기능을 제한된 형태로 유지하는 설계입니다. | 오래되거나 불완전한 결과를 정상처럼 보여주면 조용한 오류가 됩니다. | 어떤 기능이 저하됐는지 표시하고 실패를 감지할 수 있나요? |
| **feature flag** | 배포된 코드 경로를 설정이나 조건으로 켜고 끄는 장치입니다. | 사용자 집단별 동작 차이, 오래된 분기, 잘못된 기본값이 누적될 수 있습니다. | 대상·기본값·소유자·제거 조건과 긴급 전환 검증이 있나요? |

## 실패와 복구

| 용어 | 행동·상태 | 가능한 부작용 | 확인 질문 |
|---|---|---|---|
| **rollback** | 배포·설정·데이터 변경을 사전에 정한 이전 정상 상태로 되돌리는 운영 절차입니다. | 코드만 되돌려 데이터 스키마·외부 계약·사용자 생성 데이터가 불일치할 수 있습니다. | 되돌릴 대상, 기준점, 실행 순서, 검증, 불가한 변경이 문서화됐나요? |
| **revert** | 보통 기존 Git 커밋의 효과를 반대 변경의 새 커밋으로 취소합니다. | 후속 변경과 충돌하거나 코드 효과만 취소하고 외부 부작용은 남길 수 있습니다. | 취소할 커밋과 후속 의존성, 별도 데이터·배포 조치를 확인했나요? |
| **reset** | Git 브랜치·스테이징·작업 상태를 특정 지점으로 옮깁니다. | 옵션에 따라 로컬 변경과 도달 가능한 이력을 잃을 수 있습니다. | 정확한 대상·모드·영향 파일과 reflog·백업 같은 복구 경로가 있나요? |
| **retry** | 실패한 작업을 같은 목적에 대해 다시 시도합니다. | 요청·결제·메시지·배포가 중복되거나 장애를 증폭할 수 있습니다. | 일시 오류인가요, 중복 방지 키와 횟수·간격·중단 조건이 있나요? |
| **timeout** | 정한 시간 안에 끝나지 않은 대기를 중단하거나 실패로 판정합니다. | 호출자는 멈췄어도 서버 작업이 계속돼 재시도와 중복될 수 있습니다. | 어느 구간의 시간 제한이며 원격 작업 취소와 후속 상태 조회가 되나요? |
| **backoff** | 반복 실패 시 재시도 간격을 점차 늘립니다. | 상한·무작위 지연이 없으면 많은 클라이언트가 동시에 재시도할 수 있습니다. | 최대 대기·jitter·최종 실패 처리가 있나요? |
| **idempotent** | 같은 요청을 여러 번 수행해도 최종 효과가 한 번 수행한 것과 같은 성질입니다. | 일부 단계나 외부 시스템이 멱등하지 않으면 중복 부작용이 남습니다. | 어떤 범위와 키·보존 기간에서 성립하며 실제 중복 요청을 시험했나요? |
| **circuit breaker** | 반복 실패한 외부 호출을 잠시 차단해 연쇄 장애를 줄이는 패턴입니다. | 잘못된 임계값은 정상 요청까지 막거나 오래된 fallback을 지속할 수 있습니다. | 차단·시험·복구 조건과 사용자에게 보이는 fallback이 무엇인가요? |

## 실행 환경과 권한

| 용어 | 행동·상태 | 가능한 부작용 | 확인 질문 |
|---|---|---|---|
| **sandbox** | 파일·네트워크·프로세스 접근 범위를 제한해 실행을 격리하는 환경 또는 정책입니다. | 격리는 완전한 무해를 뜻하지 않으며 허용 경로 안의 삭제, 비밀 읽기, 별도 승인된 네트워크 작업은 가능할 수 있습니다. | 실제 허용 경로·명령·네트워크·비밀 범위와 우회·승인 규칙은 무엇인가요? |
| **permission / approval** | 특정 주체가 행동할 수 있는 권한 / 그 행동을 진행해도 된다는 사용자의 결정입니다. | 한 번의 승인을 세션 전체나 다른 대상에 재사용하면 의도보다 넓은 변경이 생길 수 있습니다. | 누가, 어떤 명령·경로·네트워크·시간 범위를 승인했나요? |
| **workspace-write** | 일부 제품이 지정 작업 공간 내부 쓰기를 허용하는 정책에 붙인 이름입니다. | 저장소 밖·숨김 파일·심볼릭 링크·네트워크·외부 서비스는 별도 정책이고, 작업 공간 안에서는 파괴적 변경도 가능할 수 있습니다. | 어느 제품·버전의 정책이며 정확한 쓰기 경계와 별도 승인 항목은 무엇인가요? |
| **read-only** | 일부 제품이 변경을 제한하는 정책이나 모드에 붙인 이름입니다. | 읽기 명령도 임시 파일, 로그, 프로세스, 네트워크, 외부 조회 부작용을 만들 수 있습니다. | 무엇이 읽기 전용이며 명령·임시 저장·네트워크까지 제한하나요? |
| **worktree** | 같은 Git 저장소의 다른 브랜치를 별도 작업 폴더에 체크아웃하는 기능입니다. | DB·포트·캐시·환경변수·외부 서비스는 자동 격리되지 않고 폴더 삭제 시 미커밋 변경을 잃을 수 있습니다. | 기준 브랜치·경로·미커밋 상태와 공유 자원 충돌을 확인했나요? |
| **branch** | 커밋 이력의 특정 작업선을 가리키는 이동 가능한 이름입니다. | 오래된 기준이나 잘못된 병합 대상을 쓰면 충돌과 누락이 생길 수 있습니다. | 기준 커밋, 최신화 시점, 병합 대상이 무엇인가요? |
| **remote** | 로컬 Git이 이력을 주고받도록 등록한 다른 저장소입니다. | 네트워크 주소뿐 아니라 로컬 경로도 대상이 될 수 있습니다. fetch는 받아 온 객체와 참조를 로컬에 기록하고, push는 대상 저장소의 참조를 바꿀 수 있습니다. | 어떤 주소나 경로를 가리키며, 어느 저장소의 무엇이 바뀌나요? |
| **origin** | clone이나 원격 추가 때 흔히 정하는 remote 이름입니다. | 예약어·GitHub 자체라고 오해하면 여러 원격에서 잘못된 대상을 선택할 수 있습니다. | 실제 URL과 push 대상은 무엇인가요? |
| **remote-tracking branch** | 마지막 원격 통신 때 로컬 Git이 기억한 원격 브랜치 상태입니다. | fetch 전 값은 오래됐으므로 실시간 원격 상태로 단정할 수 없습니다. | 마지막 fetch 시점과 실제 원격 확인 여부가 언제인가요? |
| **fetch / pull / push** | 원격 이력 가져오기 / 가져와 현재 브랜치에 통합하기 / 로컬 이력을 원격으로 보내기입니다. | pull은 로컬 이력을 바꾸고 push는 CI·알림·배포·협업자 상태를 촉발할 수 있습니다. | 대상 remote·branch·통합 방식·외부 쓰기 승인을 각각 확인했나요? |
| **scope** | 작업·검증·권한이 영향을 미치는 경계입니다. | 범위가 모호하면 완료 주장이나 승인이 파일·기능·사용자·데이터·환경으로 과도하게 확대될 수 있습니다. | 포함·제외 대상과 시간·환경 경계를 명시했나요? |

## 검증과 산출물

| 용어 | 행동·상태 | 가능한 부작용 | 확인 질문 |
|---|---|---|---|
| **build** | 소스를 실행·배포 가능한 형태로 변환하며 구조·참조 문제를 검사합니다. | 생성 파일이 바뀌고 캐시·프로세스·네트워크를 사용할 수 있으며 테스트·배포 성공까지 보장하지 않습니다. | 어떤 소스와 설정으로 만들었고 종료 코드·오류 수·산출물이 무엇인가요? |
| **artifact** | 빌드·테스트·조사 작업이 생성해 배포·검토·보관할 수 있는 결과물입니다. | 민감정보나 오래된 설정을 포함하거나 출처 불명 상태로 재사용될 수 있습니다. | 소스 커밋·설정·생성 명령·해시·보존 위치를 추적할 수 있나요? |
| **lint** | 정적 규칙으로 코드·문서의 문법, 스타일, 알려진 패턴 문제를 찾습니다. | 자동 수정 모드라면 파일을 바꿀 수 있고 통과해도 실제 동작을 보장하지 않습니다. | 검사 범위·규칙·수정 모드·경고 수를 확인했나요? |
| **type check** | 값과 인터페이스의 선언된 타입 호환성을 정적으로 검사합니다. | 생성 캐시가 생길 수 있고 런타임 데이터·외부 응답의 실제 값은 확인하지 못합니다. | 어떤 설정과 파일 범위였고 런타임 경계는 별도로 검증했나요? |
| **test** | 에이전트의 실행 로그에서는 보통 특정 조건에서 프로그램을 실행해 결과를 기대값과 비교했다는 뜻입니다. 테스트에는 실행 없이 검토하는 정적 테스트도 있으므로, 이 표시만으로 검사 방식과 범위를 확정하지 않습니다. | DB·파일·네트워크를 실제로 바꾸거나 fixture를 오염시킬 수 있습니다. | 실행된 테스트 수·환경·격리·실패·skipped와 검증하지 않은 범위가 무엇인가요? |
| **fixture** | 테스트가 반복 가능하게 쓰도록 준비한 입력 데이터·파일·객체·환경 상태입니다. | 실제 데이터로 오인하거나 공유 fixture를 수정하면 테스트 간 누수와 개인정보 노출이 생길 수 있습니다. | 생성·초기화·정리 방식과 가짜 데이터 여부가 명확한가요? |
| **smoke test** | 배포나 변경 뒤 핵심 경로가 기본적으로 실행되는지 빠르게 확인합니다. | 외부 서비스 호출·테스트 계정 변경이 생길 수 있고 깊은 경계 조건·정확성을 대신하지 못합니다. | 어떤 핵심 경로와 환경을 실제로 실행했고 무엇은 확인하지 않았나요? |
| **snapshot test** | 큰 출력이나 UI 구조의 기준본을 저장하고 이후 결과와 비교합니다. | 차이를 검토하지 않고 갱신하면 결함이 새 기준으로 승인됩니다. | 기준본의 출처와 모든 변경 이유를 사람이 검토했나요? |
| **coverage** | 테스트가 실행한 코드·분기·조건 범위를 수치로 나타냅니다. | 수치 목표만 맞추면 중요한 요구·오류 경로가 비어도 품질이 높아 보일 수 있습니다. | 어떤 coverage 종류이며 중요한 행동·위험과 연결됐나요? |
| **acceptance criteria** | 기능이 완료됐다고 판단할 관찰 가능한 조건입니다. | 모호하거나 범위가 빠진 기준은 잘못된 완료 판정을 만듭니다. | 사용자 행동·입력·출력·오류·환경이 구체적인가요? |
| **evaluator** | 에이전트 결과를 정한 기준으로 채점하거나 판정합니다. | 기준 편향·오탐·게임 가능성 때문에 실제 사용자 가치와 다른 점수를 낼 수 있습니다. | 평가 데이터·기준·한계와 사람 검토가 필요한 경계를 밝혔나요? |
| **exit code** | 명령 프로세스가 끝나며 정의된 성공·실패 상태를 숫자로 반환합니다. | 0을 제품·배포·사용자 흐름 전체 성공으로 확대 해석할 수 있습니다. | 어느 명령의 코드이며 로그의 오류·경고 수와 후속 검증이 무엇인가요? |
| **stdout / stderr** | 프로그램의 일반 결과 출력 / 오류·경고·진단 출력 스트림입니다. | 출력이 잘리거나 stderr가 있어도 종료 코드는 0일 수 있고 비밀이 로그에 노출될 수 있습니다. | 전체 요약·잘린 구간·실행 위치·비밀 마스킹을 확인했나요? |
| **passed / failed / skipped** | 검사 통과 / 기준 미달 또는 실행 실패 / 조건 때문에 미실행 상태입니다. | skipped를 성공으로 세거나 일부 범위의 passed를 전체 완료로 확대할 수 있습니다. | 각 수량·대상·skip 이유와 전체 모수가 무엇인가요? |

## 오류와 관측

| 용어 | 행동·상태 | 가능한 부작용 | 확인 질문 |
|---|---|---|---|
| **error** | 작업이 기대한 조건대로 완료되지 않았음을 나타내는 상태나 기록입니다. | 원인과 증상을 혼동하거나 일시 오류를 영구 결함으로 판단할 수 있습니다. | 최초 실패 시점·입력·환경·재현 조건과 사용자/시스템/일시 오류 구분이 있나요? |
| **warning** | 즉시 실패는 아니지만 위험이나 비정상 가능성을 알리는 신호입니다. | 성공 로그 사이에서 무시하면 이후 데이터 손상·호환성 문제·보안 위험으로 이어질 수 있습니다. | 영향 범위와 지금 조치할지 추적할지 결정했나요? |
| **stack trace** | 오류가 어떤 함수 호출 경로를 거쳐 발생했는지 보여주는 기록입니다. | 경로·인수·비밀이 노출될 수 있고 마지막 줄만 보면 최초 원인을 놓칠 수 있습니다. | 최초 예외, 자신의 코드 위치, 실행 버전, 민감정보를 확인했나요? |
| **log** | 사건과 문맥을 시간 순으로 기록한 데이터입니다. | 비밀·개인정보가 남거나 과도한 양과 비용, 잘못된 시간 순서가 생길 수 있습니다. | 수준·시각·상관 ID·마스킹·보존 정책이 적절한가요? |
| **trace** | 한 요청이 여러 구성요소를 통과한 경로와 소요 시간을 연결한 기록입니다. | 샘플링과 누락 구간 때문에 전체 요청의 대표값으로 오해할 수 있고 식별자가 노출될 수 있습니다. | 모든 핵심 구간과 샘플링률, 실패 span, 개인정보 범위를 확인했나요? |
| **telemetry** | 로그·지표·트레이스처럼 시스템이 전송·저장하는 운영 관측 데이터입니다. | 네트워크 전송, 비용, 개인정보·비밀 수집, 장기 보존이 발생할 수 있습니다. | 수집 주체·목적·범위·보존·삭제·옵트아웃 정책이 무엇인가요? |

## 컨텍스트와 장시간 작업

| 용어 | 행동·상태 | 가능한 부작용 | 확인 질문 |
|---|---|---|---|
| **context window** | 모델이 한 번의 추론에서 고려할 수 있는 입력·대화 범위입니다. | 오래되거나 충돌하는 정보가 중요한 근거를 밀어내고, 큰 용량을 모두 정확히 쓴다고 오해할 수 있습니다. | 실제 포함된 입력, 잘린 구간, 우선순위와 최신성을 확인했나요? |
| **context engineering** | 작업에 필요한 정보·도구·메모리를 선택·배치·갱신하는 설계입니다. | 과도한 정보와 오래된 규칙, 비밀·개인정보가 모델이나 도구에 노출될 수 있습니다. | 관련성·출처·최신성·권한·충돌 해결 기준이 있나요? |
| **compaction** | 긴 대화나 도구 출력을 요약해 컨텍스트 사용량을 줄이는 과정입니다. | 결정 근거·예외·정확한 오류·미완성 작업이 사라지거나 잘못 요약될 수 있습니다. | 저장소와 원문 증거로 중요한 사실을 다시 확인했나요? |
| **handoff** | 다음 에이전트나 세션이 안전하게 이어받도록 상태·결정·다음 행동을 전달합니다. | 대화 요약만 넘기면 실제 Git 상태·실패·권한 경계가 누락될 수 있습니다. | 경로·커밋·dirty 상태·검증·실패·미해결 위험·금지 행동이 포함됐나요? |
| **memory** | 세션을 넘어 저장하거나 다시 불러오는 사용자·프로젝트 정보입니다. | 오래되거나 잘못된 기억, 개인정보가 이후 판단에 재사용될 수 있습니다. | 출처·작성 시점·현재 재검증·삭제·수정 방법이 있나요? |
| **sub-agent** | 큰 작업의 일부를 별도 맥락에서 수행하는 하위 에이전트입니다. | 공유 작업 폴더에서 중복·충돌이 생기고 입력 부족으로 다른 결론을 낼 수 있습니다. | 작업 경계·입력·산출물·편집 파일·통합 책임이 분리됐나요? |
| **harness** | 에이전트가 작업하는 저장소·도구·규칙·권한·테스트·피드백 환경 전체입니다. | 취약한 권한·검증·상태 관리가 반복 작업 전체의 오류를 증폭할 수 있습니다. | 어떤 구성요소가 행동을 제한하고 결과를 검증하며 실패를 기록하나요? |
| **loop** | 관찰·판단·행동·평가를 반복하는 실행 흐름입니다. | 정지 조건이 없으면 비용·외부 호출·변경·오류가 반복될 수 있습니다. | 반복 한도·사람 승인·상태 저장·성공과 실패 종료 조건이 있나요? |

## 빠른 해석 공식

낯선 로그를 만나면 다음 네 질문을 적용하세요.

1. **대상**: 무엇의 상태나 변경을 말하나요?
2. **보장**: 실제로 무엇까지 보장하나요?
3. **부작용**: 파일·데이터·네트워크·Git에 무엇이 바뀌나요?
4. **증거**: 어떤 명령과 출력으로 확인할 수 있나요?

이 네 가지가 없으면 용어를 이해했다기보다 익숙하게 들리는 상태에 가깝습니다.
